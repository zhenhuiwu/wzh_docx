# 文档记忆、全文编辑与 Word 导出检查

2026-10-03。前端 http://localhost:5173，后端 http://127.0.0.1:8001。沿用 SQLite 和现有 AI 配置。

## 已实现

- 编写记忆按文档保存在 SQLite 的 `document_memory_events` 和 `document_memory`。仅在用户采纳修改并成功保存后记录要求，与正文处于同一事务；未采纳、停止或失败的草稿不进入长期记忆。
- 原始要求完整保留；模型使用最多 6000 字符的近期摘要，合并重复要求、注明摘录，必要时通过 `search_writing_memory` 查询完整历史。当前要求与当前文档优先。界面的“编写记忆”显示最近五条原始要求，可清除当前文档记忆。
- DeepAgents 使用原生 `SummarizationMiddleware` 压缩运行中的长对话，并将原始历史保留在当前运行的文件后端。跨请求恢复使用 SQLite 中已采纳的要求与当前文档，不依赖临时智能体状态。[原生压缩文档](https://reference.langchain.com/python/deepagents/middleware/summarization)、[记忆文档](https://docs.langchain.com/oss/python/deepagents/memory)。
- `AI_CONTEXT_TOKENS` 默认 32000，75% 预算触发对话压缩，保留最近四条消息；中文按较保守的字符计数估算。该值须与实际模型上下文容量一致。长文档输入有完整标题索引和明确标记的摘录，智能体可分页读取当前版本的完整章节。
- 支持“章节”“选中文字”“全文”。点击“AI 编辑全文”进入全文模式；先读完所有非空章节，再提供逐节修改草稿，预览后点击“应用全文修改”。修改既有正文，保留标题、层级、顺序；新增标题继续使用大纲。
- 全文计划限制重复/不存在的章节、非法结构及图片变化。完整生成并通过检查后才能应用，中止的全文草稿不能应用。正文保存采用版本条件更新，防止另一标签页的修改被覆盖。
- 章节、全文和手动/选区保存均执行原始 Word 的 OOXML 预检；生成和采纳均带上本次指令识别的 438C 文档类型、章节与表头规则。
- 新增“版式预览”：保存当前编辑稿后，沿用导出的 OOXML 处理并由本机 Microsoft Word 渲染 PDF，显示编辑稿真实分页；原稿预览与编辑稿预览分开缓存。预览校验当前版本，翻页回到页首。

## Word 修复

1. 新段落继承正文格式时不复制分节设置，避免误增分节。
2. 按每个实际图片引用解析，保留同一图片多次出现的记录。
3. 删除或替换复杂内容也执行保护检查，防止图片、Word 域、合并表格及分节内容丢失。
4. 全文草稿预览显示原有图片；导出继续在原始 DOCX 上修改 OOXML，保留原稿样式、媒体和页眉页脚。

## 明确边界

复杂 Word 结构无法安全修改时，保存或导出会明确拒绝。当前可编辑画布是正文编辑视图，字体、图片显示尺寸和分页不等同于 Word 的逐像素渲染；编辑稿的精确分页使用“版式预览”，原稿使用“查看原稿”。预览依赖本机 Microsoft Word；当前电脑已实际渲染通过。导出格式以原始 DOCX 和实际 Word 渲染为准。本次样例检查通过，不能据此声称任意复杂 Word 都可无损改写。
