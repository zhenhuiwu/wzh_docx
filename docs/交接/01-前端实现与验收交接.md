## 3 六模块的交互落点

- 工作台：真实待办、阻塞和运行任务，点击直达具体对象；不复制一套完成状态。
- 项目管理：项目资料与事实、文档块、证据、测试采集、审核交付。文档工作台采用目录、正文、依据/问题/助手的可切换布局。
- 用户管理：真实账号与权限、启停和会话处理；当前本地用户表不能被当成正式安全系统。
- 系统管理：模板和规则版本、模型/环境配置、审计；秘密不回显。
- 知识库：文件上传、解析状态、版本、检索与引用；上传完成不是处理完成。
- 智能助手：清晰的项目/文档/块范围、消息和任务卡；明确发送中、等待输入、失败、暂停与候选结果。

现有用户路由为 /system/users；方案建议 /users 并兼容旧路径，但这是计划改动，不是已经存在的路由。不要在多个模块复制独立任务队列、草稿或相互矛盾的状态。

## 4 每个页面和表单的完成要求

### 列表与导航

查询条件、分页、总数和排序来自同一请求快照；变更查询回有效页，重置确实清条件，旧慢请求不能覆盖新结果。必须真实点击验证，不只证明存在按钮。无权限内容和统计都不能显示。

长名称换行或提供可访问的完整内容入口；窄屏优先展示名称、状态与主动作，其余展开。刷新深链、返回列表、页码恢复要与实际路由行为一致。

### 表单和编辑

每个输入有 label；字段错误指向字段；提交中和 disabled 有意义且可见；失败保留输入，成功得到服务端确认才关闭。离开未保存内容要处理，冲突保留双方版本；新 AI 草稿先比较，不盖掉人工修改。

固定标题、公共事实直填和程序编号不由自由富文本编辑。模板未适配、模型未配置或缺权限时显示真实原因，不用定时器返回成功。开发夹具必须与业务数据隔离，且不能混入交付默认页面。

候选内容、当前工作稿和批准版的行为按 [开发契约补充](D:/项目/智能化/docs/完整开发方案/08-开发契约与遗漏补充.md) 实现：“生成完成”只说明候选持久化，只有显式采用才更新当前稿；采用时发生版本冲突必须保留双方内容。

### 助手与任务

中文输入法确认阶段不能误触 Enter 发送。消息失败可恢复输入，页面关闭不代表后台任务取消。生成、重跑测试、重新截图和重新导出是不同操作，不能合并为模糊的“重试”。

暂停先是请求暂停，安全停稳后才显示已暂停。待核实的外部提交不可直接重放；接管浏览器只有在安全通道与排他控制真正可用时显示有效入口。

### 所有页面的必要状态

加载中、无记录、无匹配、局部失败、权限不足、版本冲突分别处理。错误不能伪装成空列表。无后台接口时明确未接入，不宣称功能完成。

## 5 布局与截图协议

先设计375，再扩展到768、1280、1440。小屏采用单列和面板切换；文档正文优先，不挤出四个窄栏。宽表或 Word 预览可以在自身容器内有明确滚动/缩放，页面本身不能靠隐藏溢出来遮住按钮。

当前平台前端验收地址固定为 http://localhost:5173。产品未来用于功能测试的目标 Web 地址是另一个授权配置，不能混淆，更不能随便操作生产前端。

每次修改前端后必须：

1. 检查当前服务与端口；已有本项目实例时复用，不另开冲突进程。
2. 打开固定地址，进入所有受影响页面，走实际操作流程。
3. 以375、768、1440宽度截图，另检查1280；核对实际截图图片，而不只 DOM/接口/控制台。
4. 至少覆盖正常、加载、空、错误及本次新增的重要状态；提交、查询、分页等有操作前后证据。
5. 检查对齐、溢出、可点区域、对比度、键盘焦点和禁用/错误可见性。
6. 不合格就修改后重新截图，保留能对应当前版本的最后结果。
7. 提交截图绝对路径、操作记录、检查结果和剩余问题。

没有可用浏览器或截图工具时，明确“代码已改，视觉验收未完成”，不能假报完成。由具备工具的执行者补验后才能通过对应门槛。不能删除截图要求来适应工具限制。

## 6 运行与验证提示

先检查 [package.json](D:/项目/智能化/web/package.json)、现有进程和依赖，不假设所有 test/lint 脚本都存在。目前可见的脚本包括 dev、build、preview；build 包含类型检查与构建。

经用户授权实施时可使用以下已有脚本；本交接准备未执行：

~~~text
npm --prefix "D:/项目/智能化/web" run dev
npm --prefix "D:/项目/智能化/web" run build
~~~

验收仍使用5173，不以 preview 常用的其他端口替代。端口被占用先识别进程与所属任务，不杀未知服务、不静默换端口。需要后台启动时遵循执行环境的窗口、权限和进程管理规则。

构建通过只是一个检查，不代表真实接口、权限、排版和交互通过。后端未完成时，可在明确标记的隔离开发环境使用测试夹具检验视图，但交付报告必须区分“夹具验证”和“真实联调”。

## 7 后续请求评审需要给什么

给出页面名称和路由、用户要完成的动作、当前与期望差异、修改文件、实际截图、复现步骤、视口、数据/错误状态，以及你希望评审的是交互、排版、接口还是实现问题。

不要只发一句“帮我优化界面”。优先请评审具体问题，例如“375宽度下操作栏挤占正文，哪种折叠方式符合方案”或“单块生成与人工编辑冲突时的确认行为是否正确”。评审建议不代替接手方运行代码与截图验收，也不能自行批准新的数据访问权限。
