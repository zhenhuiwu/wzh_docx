## 二、架构对比

### 重构前（复杂）

```
模板
  └─ 模板版本
      └─ 块定义 (blocks)
          └─ 提示词、依赖、校验

文档实例
  └─ 文档块
      └─ 块修订
          └─ 候选、当前、批准

项目
  ├─ 成员管理
  ├─ 资料管理
  ├─ 事实管理
  └─ 审核流程
```

**问题**:
- 过度设计，块级管理复杂
- 多版本、多状态难以维护
- AI 难以直接编辑块结构

### 重构后（简化）

```
模板组
  └─ 文档模板 (Word 文件)
      └─ 格式模板 (样式定义)

项目
  └─ 文档实例
      ├─ Markdown 内容
      ├─ 格式模板
      └─ 文档大纲
```

**优势**:
- 结构清晰，易于理解
- Markdown 格式 AI 友好
- Word 格式通过模板保持
- 减少 80% 的数据表

## 三、核心功能实现

### 1. Word 处理流程

```
上传 Word 文档
    ↓
解析 (python-docx)
    ├─ 提取结构：标题、段落、列表、表格
    ├─ 提取样式：字体、字号、颜色、对齐
    └─ 转换为 Markdown
    ↓
存储到数据库
    ├─ markdown_content (可编辑)
    └─ format_template (样式定义)
    ↓
编辑 (Markdown)
    ↓
导出 Word
    ├─ 解析 Markdown
    ├─ 应用格式模板
    └─ 生成 Word 文件
```

### 2. 文档编辑器

**布局设计** (1920×1080):

```
┌─────────────────────────────────────────────────┐
│ 工具栏: 文档名 | [保存] [预览] [导出Word]        │
├──────────┬──────────────────────┬───────────────┤
│          │                      │               │
│  大纲树  │   Markdown 编辑器     │   预览面板    │
│  250px   │       1fr            │    400px      │
│          │                      │               │
│  # H1    │  # 第一章            │  [HTML渲染]   │
│  - H2    │                      │               │
│  - H2    │  ## 1.1 背景         │               │
│  # H1    │                      │               │
│          │  正文内容...         │               │
│          │                      │               │
└──────────┴──────────────────────┴───────────────┘
```

**功能特性**:
- ✅ 自动保存（3秒防抖）
- ✅ 实时预览
- ✅ 大纲自动生成
- ✅ Markdown 工具栏
- ✅ Tab 键缩进支持
- ✅ 未保存提示

### 3. 模板管理

**模板组结构**:
```
软件项目模板
├── 需求规格说明书.docx
├── 设计文档.docx
├── 测试报告.docx
└── 用户手册.docx
```

**操作流程**:
1. 创建模板组（名称、分类、描述）
2. 上传 Word 文档到模板组
3. 系统自动解析格式模板
4. 创建项目时选择模板组
5. 自动创建所有文档实例

## 四、技术选型

| 技术点 | 选择 | 理由 |
|--------|------|------|
| Markdown 编辑器 | 原生 textarea + 工具栏 | 第一版轻量，后续可升级 CodeMirror 6 |
| Word 解析 | python-docx | Python 官方推荐，成熟稳定 |
| Markdown 渲染 | marked.js | 轻量、快速、可扩展 |
| 预览方案 | 服务端 HTML | 确保与导出一致 |
| 样式保持 | 格式模板 (JSON) | 提取原始样式，应用到导出 |
