# AI 浏览器实时测试

更新日期：2026年10月4日。

## 使用入口

在 http://localhost:5173 的“测试用例管理”中新建测试任务：选择项目、上传测试计划 Word，填写前后端源码目录和运行中的服务地址，按需填写测试账号、密码、允许修改的测试数据范围。功能测试方式默认“AI 实时操作”；旧任务继续使用原来的固定步骤方式。

源码目录是运行后端服务的电脑上的绝对目录，服务地址是该电脑能够访问的 HTTP/HTTPS 地址。本轮没有新增自动启动外部项目的能力，目标服务需要先启动。后端会过滤凭据文件、依赖目录、目录穿越和链接文件。

提取测试项后可以勾选运行或单项运行；执行结果包含真实动作、断言结果、步骤截图和历史记录，并可下载补充了实测记录的 Word 报告。

## 内置技能与执行器

- `server/workspaces/browser-skills/agent-browser/SKILL.md` 是实际加载的适配版技能；`references/` 保留用户 ZIP 的原始说明、元数据和 SHA256。
- 用户上传的 ZIP 只有技能资料，没有浏览器运行程序。项目复用现有 Playwright Chromium，没有新增全局 CLI 或另一套浏览器引擎，也没有执行包中的 shell 模板。
- `server/app/test_browser_agent.py` 使用 Python DeepAgents，提供 `browser_observe`、`browser_act`、`browser_assert(index)`、`finish_case` 和受限源码读取工具。
- 页面观察返回当前 URL、可见文字和控件引用；每次动作之后必须重新观察，不能沿用旧引用。同轮不能并行操作浏览器。
- 中途断言在对应页面执行，结束时核对剩余的原始断言。预期来自确定的用例，模型不能改写预期或自行提交“通过”。
- 运行使用独立浏览器上下文，仅允许配置的服务 origin，限制外部请求、WebSocket、弹出窗口；禁止默认 task、写文件和 shell 工具。单用例有操作数和时间上限，等待模型时也能响应停止请求。
- 每步保存完整 1920×1080 截图及可选操作区域截图。密码框被遮挡；结果页缩略图和 Word 报告优先使用清晰的区域图，打开预览显示完整原图。
- 截图目前作为本地证据保存，模型收到的是 DOM 文字和控件信息，不能据此宣称完成了像素级排版、遮挡或配色检查。

## 本轮检查发现并修复的问题

1. 原执行器只按预先生成的步骤运行，没有执行时的页面反馈。新增实时观察与单步决策，固定步骤模式仍可选择。
2. 原分析提示允许主动增加边界、异常及其他类型的测试项，与计划限定的范围有冲突。改为按计划要求的类型、范围和数量提取，源码只补充实现依据。
3. 状态区的正文不等于控件可访问名称。支持匿名角色定位并明确提示规则，正文仍通过固定的精确文本断言核对，不把定位修复当成修改预期的理由。

## 验收记录

本轮使用隔离的动态登记页面、专门生成的中性 Word 计划和报告模板，调用当前已配置的 AI。实际验收证据存放在 `server/.qa-browser-agent-20261004/`。不将隔离样例当作用户外部真实项目的验收，不向模型发送用户现有业务文档。

自动回归覆盖：动态控件反馈、原始中途断言、错误预期、过期引用、服务范围、停止、密码遮挡、AI 伪报通过及并行动作拒绝。测试使用独立数据库，前端按1920×1080实际点击并查看截图；报告使用本机 Word 打开后导出 PDF 并核对渲染。

最终结果：12 项回归通过，前端构建通过；真实 AI 最终执行用时 18.19 秒，7 个实际步骤均保存完整截图及清晰区域图，2 个原始断言通过。重新提取严格限定为计划中的 1 个用例。Word 报告 5 页、7 张截图，原有正文、样式和页眉保留，并查看了渲染页面。真实执行历史保留了定位缺陷导致的失败，未将失败改成通过。

隔离验收任务、项目和上传文件在检查后归档到上述目录，不保留在业务项目列表中。数据库记录与全部运行截图备份在 `evidence/`，`verification.json`、`word-verification.json`、`downloaded-report.docx` 及界面截图可复查。

真实项目验收仍需要用户提供该项目的计划 Word、源码目录、启动后的服务地址、测试账号和允许修改的数据范围。并发测试当前是受限的 HTTP GET/HEAD 压测，单元测试支持已有 pytest / Node 原生测试，不能以此宣称支持所有语言或所有压测场景。
