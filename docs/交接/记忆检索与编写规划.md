# 记忆检索与编写规划

2026年10月4日。前端固定为 http://localhost:5173，后端为 http://127.0.0.1:8001，数据库仍为 SQLite。本轮优化后端记忆和 DeepAgents 编写流程，没有新增前端控件。

## 已实现

### 按任务读取记忆

`server/app/document_memory.py` 新增 `load_task_memory`。编写时读取当前标题的章节要求和整篇要求，分别留出近期、早期记录的候选额度；不再仅向模型发送最近记录的统一摘要。整篇编辑读取某一章节时，还会返回该章节的相关要求。

完整已采纳记录仍保存在 `document_memory_events`，草稿生成不会写入记忆；文档修改成功后，在同一个 SQLite 事务中记录要求。旧选区改写指令保留在原始历史中，但不自动用于下一次改写。相关要求按原文提供并去重，超预算的要求可以按标题或关键词分页查回；当前要求优先，历史冲突参考较新版本，项目事实以当前项目概述和文档为准。

摘要查询限制81条，任务候选查询分别限制32、32、8、8条，避免每次采纳都扫描并处理全部历史。迁移 `106_document_memory_target.sql` 增加文档、范围、标题和版本的查询索引。图表生成也改用相关记忆检索。

### 先准备，再写正文

`server/app/document_agent.py` 新增受控 `prepare_document_edit` 工具及 `_WritingPreparation` 中间件：

1. 开始时加载当前项目概述，将当前要求、编辑范围、目标标题及来源版本固定在模型请求中。
2. 读取必要资料与技能。全文模式必须连续分页读完所有非空章节，含标题前正文；声明实际需要修改的章节。
3. 单独调用准备工具。与其他读取工具同轮调用时，返回可纠正提示，避免并行执行时的准备竞态。
4. 准备完成后，把待修改部分的完整原文、对应规则和记忆固定提供给正文模型，并关闭全部工具。
5. 服务端核对全文返回的实际修改章节属于已声明范围，再沿用技能、图片和原生 Word 校验；用户采纳后才保存。

框架继续压缩过程历史，但固定任务与完整待修改原文不依靠压缩摘要保存。最后一轮移除重复发送的原文，保留技能资料、背景和未修改章节的读取结果；不足以容纳完整修改原文时明确要求缩小范围，不静默截断。

章节/选区的主模型调用上限为12轮、工具调用上限24次；全文为48轮、96次。辅助摘要模型调用不属于上述主模型轮数，不能把这些数字称为全部 API 请求次数。达到上限时提供缩小范围的提示。

默认的文件写入、执行与通用子智能体工具不向编写模型开放，工具执行层也拒绝它们。规划过程、工具消息和框架摘要不进入正文流。

实际配置的思考模型不支持强制 `tool_choice="required"`，因此没有修改用户模型配置。对于提前直接回答的模型，程序丢弃该回答并明确提示先调用准备工具，最多提醒两次；仍未准备则拒绝。被丢弃的回答也从后续模型消息中移除，不作为事实依据。

## 当前边界与后续顺序

1. 记忆仍按文档隔离；当前项目概述作为事实输入，但尚无跨文档共享的项目事实与术语库。下一步应优先建立用户可编辑的项目术语、已确认事实和来源，避免把模型猜测或临时操作当成长期事实。
2. 章节记忆仍按标题文字匹配，标题改名、同名标题及重排没有稳定章节标识。需要稳定章节标识后，才能可靠追踪跨版本的章节要求和关联。
3. 历史检索有容量限制，并未实现语义向量检索或自动判定要求永久有效。超过候选窗口或上下文预算的要求可能需要主动检索，不能声称任何历史要求都必定自动召回。
4. 已采纳要求持久化；未采纳的智能体计划和运行状态仅存在于本次请求。没有后台断点续写或自动恢复整篇规划。大文档目前宜分章节处理。
5. 后续优先实现采纳前的修改对比、文档历史版本与回滚，再考虑可恢复的分章节规划。保留单人使用的简单流程。

以上后续项尚未实现。本轮测试也不等于所有真实 Word 模板都已逐页验收。
