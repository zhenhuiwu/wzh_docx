## 1 先知道要做什么

工作区为 D:/项目/智能化。产品是公司内网的项目文档编制、知识检索与测试取证系统，不是普通聊天页或营销站。

六个一级模块：工作台、项目管理、用户管理、系统管理、知识库、智能助手。项目内一组文档相互关联；文档绑定 Word 模板、专属 Skill 和块级提示词；一个逻辑 Agent 共享项目记忆，按多轮小任务编写并调用受控工具。函数级单元测试、实际前端功能测试、用户手册截图都要保存真实执行记录，文档再引用证据。

本文件是导航与交接说明，不新增权限，也不能代替接手环境中的系统规则、用户授权或仓库固定指令。发现冲突应指出并澄清，不凭技能里的其他框架示例推翻当前 Vue3 约束。

需要直接转交启动指令时，使用 [接手启动提示词](D:/项目/智能化/docs/交接/02-接手启动提示词.md)。

已补充 [直接执行规格](D:/项目/智能化/docs/执行规格/00-执行入口.md)。完成必要接手核对后，按DEV任务和对应operationId产出实际文件，不要再用重写总体方案代替实施。审批范围和未知真实环境仍按原决策记录处理。

## 4 不能丢失的业务原则

- 一个项目管理一组实际文档，同一模板允许按用途产生多个文档实例。
- 界面按名称、项目、用途和版本识别模板和文档，不显示或要求填写其编号；内部 ID 仅用于数据关联。
- 同一个 Agent 分多轮做小任务；不是多 Agent 各写一篇，也不是一次整篇生成再拆开。
- 项目记忆持久化，已确认事实、任务草稿、原始资料和真实执行证据分开。
- 每个块有指定输入、输出、提示词、依赖与校验，程序限制写入范围。
- 事实和测试数值优先程序直填，模型只组织需要语言表达的内容。
- 重生成创建候选修订，不覆盖人工修改或已批准版；上游变化标影响，不改旧执行数据。
- 真实测试和手册采集共用工具但目的不同；截图不等于测试通过。
- 交付锁定模板、内容、来源和证据版本；失败可以如实写入报告，不为凑“通过”修改事实。
- Skill 不是权限边界，危险工具、来源、项目和版本检查由程序落实。

## 5 接手第一轮应该做什么

第一轮先完成有范围的接手核对：

1. 核对当前代码和运行环境，若有 Git 就查看工作区变化；保护他人未提交修改。
2. 阅读用户已批准的任务；没有明确本轮任务时，提出一个最近可验收的小任务，不自行一次实现全部六模块。
3. 列出已实现、仅原型、未实现、待验证，避免重新设计已确定规则。
4. 对拟做任务说明目标、输入、依赖、修改文件范围、风险和验收方法。涉及前端先观察实际页面与既有交互。
5. 只询问真正阻塞本轮的决策。未知模型或测试环境不阻止独立的资料与界面工作；但不能假装依赖已满足。
6. 获得相应范围的开发授权后，小步实现、测试、记录证据并回报；已有明确授权任务不必反复索要同一许可。

没有明确范围时，不升级依赖、不迁框架、不重构整站、不删除数据、不发布生产环境、不连接未授权服务。不能将“有完整开发方案”理解为批准一切副作用。

## 6 首先核实的待定事项

按当前任务需要从决策表选择：模型与协议；后端部署与数据库；身份来源；测试语言/框架；被测 Web 地址、登录方式和授权；Word/WPS版本、字体与合格样例；首批文档清单与编号栏政策；知识库格式；审批和保密范围。

模型密钥、密码和真实业务数据不写进交接文件或公开聊天。需要用户提供时要求脱敏调用样例、凭据引用或批准的安全渠道。没有测试授权时只做假数据隔离样例，不操作实际产品或生产环境。

参考16—18周计划有人员和范围假设，S0后需要重估，不是接手 AI 已获得的硬工期承诺。

## 7 与需求和设计评审方如何协作

接手 AI 负责当前已授权范围的实现、运行验证与真实回报；需求/设计评审可以协助解释交互、检查数据/接口和审查结果。最终业务范围、角色、安全授权与验收决定由用户或指定负责人确认。

每次请求协助附目标、当前行为、相关绝对文件路径、最小差异/错误、已试方法、截图和需要决定的一个具体问题。按回报模板给材料，不只说“界面不对”或“已经做好”。截图应提供可实际查看的文件，不能仅发路径字符串且文件不可访问。

不假设存在自动同步、自动监控或自动消息回传。由用户转交材料，或在获得对指定对象的明确通信授权后协作；当前交接包不授权启动其他 AI、向其他任务发消息或建立定时跟进。

同一个工作区避免两个执行者同时改同一文件。必要时明确文件负责范围和交接时点；后续决定以用户可核实的记录更新方案，不让两个聊天各自成为一份不同的“最终需求”。
