# Skill 管理与文档编写规范

## 2026-10-04 实现

- 系统管理最后一组新增 Skill 管理，入口 `/system/skills`。此项来自本次用户明确要求，AGENTS.md 同步更新。
- SQLite 迁移 `109_writing_skills.sql`，管理规范与可选幂等请求持久保存。首次启动提供通用技术文档、GJB438C软件需求规格说明、GJB438C软件设计说明；重启不覆盖修改或停用状态。
- 管理页支持名称/状态查询、20 条分页、新建、编辑、启停及 `.md/.txt` 编写要求导入；登录用户可读，仅系统管理员管理。
- 在文档编辑工具栏打开“编写规范”：自动匹配、不使用 Skill、选择一个 Skill；可填写本篇补充要求。一份文档锁定一份规范，避免多份规范冲突。
- 选择保存时复制服务端完整快照到 `format_template.writingSkill`，包含 Skill 名称、版本、基础类型、编写要求与硬约束。本篇要求单独保存。公共修改不会静默影响既有文档，可主动“使用最新规范”；停用阻止新绑定，已保存快照仍可使用。
- 修改文档规范会增加文档版本，记录为“编写规范”，不改正文、状态或 Word 样式；旧 AI 草稿会因文档版本冲突而拒绝采纳，历史恢复会同时恢复规范快照。

## AI 与格式约束

- 章节、选区、全文的生成、读取上下文、编写规划及采纳使用同一规范快照。显式通用/不使用模式不再被文档名称误判成438C。
- 438C基础库继续使用原有 `server/workspaces/GJB438C-DocSkill/skills/`，运行时仅暴露所需基础规范；去除项目样例事实。
- 自定义写法及本篇要求进入系统编写指令；真实性、安全、输出范围和 Word 结构规则优先于可配置内容。
- 禁用词与章节/选区字符上限为服务端硬校验，完成生成及采纳均检查；追加检查最终整节，防止分次超限。字符检查基于解析后的可见文本。
- 已显式配置规范的文档不能使用旧 `PATCH content + memory` AI 采纳入口绕过校验。现有三个专用接口正常；手工正文编辑保留原行为。
- Skill 文本不会授予 Shell、文件写入、子智能体执行等权限。
- 自然语言中的写法要求由模型遵循，并非任意语义都能机械判定。字体、页眉页脚、页面参数仍沿用 Word 模板；本次未实现通过一句 Skill 指令任意重设全部 Word 排版。
