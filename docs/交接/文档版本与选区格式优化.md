日期：2026年10月4日。接续《AI文档编写多角度检查》中尚未实现的三项工作；本记录覆盖当前实现，旧记录保留当时的检查结果。

## 已完成

### 1. 持久版本记录

- SQLite 新增 `108_document_versions.sql`，启动时已迁移。迁移前备份保存于本轮验收目录。
- 新建、手动保存、加标题、章节/选区/全文采用、插入图表、撤回均记录版本，包含正文、大纲、图片信息和有效编写记忆集合。
- 工具栏增加“版本记录”，每页5条，可对照当前稿和历史稿，并恢复所选版本。恢复执行 Word 预检和版本冲突检查，生成新版本，不抹掉之后的版本。
- 刷新页面后版本记录仍存在。旧文档从首次查看或保存时开始记录，不补造之前未保存的历史。
- 恢复正文同时恢复对应的编写记忆。记忆事件保留，用撤回标记决定是否生效；“清除记忆”停用当前要求，明确恢复旧版本时可恢复其要求。

### 2. 选区由服务端采用

- 单段正文使用源块ID、UTF-16起止偏移、精确原文和文档revision绑定；重复段落、重复词和emoji均有回归。
- 支持段内跨粗体/普通文字替换，保留未选部分格式。生成内容作为纯文本转义，换行留在原段，不意外变成标题或表格。
- 生成前校验选区位置是否能安全写回原生Word，生成结束后再次预检。包含受保护域、图片等的位置会尽早返回明确提示。
- 采用由后端一次事务保存正文、版本和记忆；不再使用浏览器 `execCommand(insertText)` 修改选区后上传整稿。
- 人工保存后，生成前重新读取源锚点，仅在全部段落顺序和文字对应时绑定新锚点，不全局查找同名文字。结构不同提供“刷新编辑稿”恢复入口。
- 跨段内容使用章节或全文编写。复杂HTML、无法证明位置的结构拒绝猜测替换。

### 3. 编辑稿继承原Word样式

- 编辑预览先生成实际编辑版DOCX，再把段落、run、列表和表格属性对应到当前编辑结构。
- 解析默认样式、继承样式、主题字体/颜色及直接格式，显示对齐、字号、颜色、混合强调、缩进、间距、编号和表格边框等。
- 原Word强调通过CSS显示，现有Markdown强调继续保留语义，避免仅打开/保存就把源格式当成新编辑。
- 修复硬换行写入Word时的双换行，以及真实Word段内换行在HTML里折叠的问题。
- 历史侧栏表格按侧栏宽度显示，主编辑稿与原生导出保持各自原稿格式。控件继续使用项目已有CSS变量和类。

## 仍存在的边界与下一步

1. **编辑HTML不是完整Word排版引擎**。真实分页、页眉页脚、复杂合并单元格和浮动对象仍需要原生Word预览；不能宣称逐像素一致。后续应评估真正的OOXML编辑器，再决定是否替换当前编辑层。
2. **长任务断点恢复尚未实现**。已采用版本可以恢复，正在生成但未采用的草稿/规划仍不能跨刷新或服务重启续写。应在稳定版本基础上持久化逐节任务状态、候选结果与输入版本，恢复时校验源版本。
3. **记忆仍按文档隔离**。项目共享事实尚未落地，应区分用户确认事实和模型推测，避免把一份文档的临时要求传播到其他文档。
4. 历史为完整快照，尚无保留期限与差量压缩；不自动删除旧版本。长期大文件使用后应先量化SQLite增长，再设计可恢复归档。
