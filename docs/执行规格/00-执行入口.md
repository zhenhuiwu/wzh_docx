## 1 这次交付的不是另一份概念方案

本目录将此前方案转成可逐项实施的页面规格、请求响应合同、任务依赖、文件范围、具体步骤和验收条件。接手AI不需要重新设计六模块，也不应以再写一篇总体方案代替代码产出。

但是设计合同不是实际后台，合成样例不是公司证据，任务卡中的任务目前全部未开始。公司模型/代码/测试地址/身份政策/Word环境等真实输入依然不能猜测。只有用户批准相应开发范围后，接手AI才执行相关写入和测试。

## 2 使用顺序

1. 先读 [AGENTS](D:/项目/智能化/AGENTS.md)，再核对 [开工输入与决策记录](D:/项目/智能化/docs/交接/04-开工输入与决策记录.md)。
2. 选择 [tasks.json](D:/项目/智能化/docs/执行规格/tasks.json) 中依赖满足、当前任务相关决策已明确的一个任务。任务编号不是执行顺序。
3. 只读取该任务对应的页面、operationId和数据schema，不把所有旧文档塞进每轮上下文。
4. 按允许文件范围实施，完成具体Given/When/Then和必要真实截图；不能只搭页面外观或返回假成功。
5. 按 [交付回报模板](D:/项目/智能化/docs/交接/03-阶段交付与问题回报模板.md) 报告真实产物、验证与未完成项。没有真实验证就不改成完成。

若用户已经授权“按本执行规格开发”，先做DEV00快速核对，然后推进已授权的就绪任务，不反复索要同一许可。没有本轮授权或触及新的高风险范围时，只报告需要的具体决定。

## 4 首版已收敛的实现选择

- 不换Vue、不加UI库。角色页只读固定角色定义，分配回用户/项目页；公共规则页只读汇总，维护回设置/模板，不建两套策略编辑器。
- 不做在线Word编辑器。先上传已标记模板副本、Skill和规则，展示解析后的块与验证；原始20模板只读。文档实例首先使用已发布模板包，未适配模板仍在模板清单作为待办，不伪装可生成文档。
- 项目软件版本从已确认事实派生；owner使用真实userId；用户原型staffId/role转换为account/globalRoles和项目成员角色，但不能自动继承本地权限。
- 查询为提交式AND、页大小默认10最大50；正文和提示词等专用限长按各自schema，不随意套说明字段的2000上限。
- AI输出只产生候选；当前工作稿与批准版独立；采用比较expectedRevision和来源快照。
- 单元与浏览器先共用DEV24的用例/运行/证据基础，再分别DEV19和DEV20适配，不能让浏览器等待尚未选择的代码语言。
- 模型、正式Office渲染和真实工具执行的不可用状态要真实呈现；测试夹具不得混进默认运行界面。

## 5 第一轮直接怎么做

DEV00只核对现状和必要输入，不改业务代码。它完成后：

- 前端范围已授权但后端选择尚未批准：可做DEV01的导航和现有状态基线，明确它不是正式后台完成。
- D02/D12已确认：从DEV02开始真实服务底座；D03/D09确认后做DEV03/04/05，不需要等待本地模型。
- 不允许先做一个会自动回答“成功”的助手，或一次性生成全部后端/前端然后跳过校验。

最小真实业务切片是“真实登录 → 当前用户与范围 → 可访问项目列表”，之后才依次进入资料/模板/知识/内容块。合同和任务图已提供对应字段与操作，不能以“还需要再设计一次架构”为由停在规划。

## 6 写入和协作规则

每项任务列明allowedWritePaths。公共入口、路由、models、迁移与共享工作台文件需要协调后再写，不能两个执行者同时覆盖。脚手架仅创建本任务需要的文件，不为未来功能建空服务。

DEV任务结束在指定reportPath写真实回报；不要直接把任务源文件not_started改成completed来代替证据。实际进度可单独维护在 D:/项目/智能化/docs/交接/回报 中，记录提交/快照与验收结论。

没有Git时不要捏造分支和提交；保护已有用户修改。不得改AGENTS或原始模板来绕过要求，不删除旧资料、不擅自连接外部模型、不操作生产环境。

## 7 验证命令和边界

在具备Python的受控环境运行基础检查：

~~~text
python "D:/项目/智能化/docs/执行规格/validate_specs.py" --structural-only
~~~

完整JSON Schema样例检查命令：

~~~text
python "D:/项目/智能化/docs/执行规格/validate_specs.py"
~~~

当前环境的jsonschema依赖不完整，缺少referencing；完整模式实际失败记录保存在 [schema-validation-unavailable.json](D:/项目/智能化/docs/执行规格/schema-validation-unavailable.json)，没有自动安装依赖。38个样例已编写，但不能宣称已完成完整schema验证。开发方在获批环境补齐依赖后运行默认模式；另有专用OpenAPI工具时可追加完整规范检查，本次没有这种通过结论。

[validation-report.json](D:/项目/智能化/docs/执行规格/validation-report.json)记录最近一次校验的真实范围。结构检查通过只代表引用、路径与任务图等一致，不代表API运行、鉴权、真实模型、代码测试、Word或UI截图已经通过。

任何前端修改仍需在http://localhost:5173实际操作、查看1920×1080截图，不得拿本目录校验结果替代。
