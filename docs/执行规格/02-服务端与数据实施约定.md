# 服务端和数据实施约定

日期：2026年9月27日。供接手AI配合OpenAPI和DEV任务卡产出代码；这是设计合同，不是已实现服务。后端语言/部署、身份政策、模型和实际测试环境仍按D01—D14确认。无需等不相关决策全部齐备才做独立任务。

## 1 合同与版本的使用方法

[OpenAPI合同](D:/项目/智能化/docs/执行规格/contracts/openapi.json)给出字段、请求/响应、权限键、状态与业务校验提示。[操作索引](D:/项目/智能化/docs/执行规格/contracts/operation-index.json)用于按operationId查目标，不需要每轮把全部合同加入上下文。

合同版本为0.1.0-design。实现时对当前任务的请求与响应严格对齐；如果必须改变，先解释影响，同步合同、页面字段、任务验收及对应测试。不能只改后端返回让前端猜。API提供的是设计目标，读合同不能替代实际调用验证。

响应封装固定为data/requestId，列表data内含items/page/pageSize/total；错误为error/requestId。JSON用camelCase，数据库可用snake_case。省略字段表示不修改，null仅用于schema允许清空的字段。内部ID用于路由与授权，不能用作模板或文档可见编号。

### 前端API层的具体约定

D:/项目/智能化/web/src/api/client.ts 统一使用原生fetch、同源凭据、/api/v1前缀和规范ApiError；错误含status/code/fieldErrors/currentRevision，requestId留诊断数据而非业务编号。JSON和FormData分开处理，FormData不手动设置multipart边界，204不强行JSON解析。支持AbortSignal以忽略旧查询，401进入真实认证流程，403不无限重试，409保留编辑输入。

GET /auth/csrf和登录会话提供CSRF值，写请求携带X-CSRF-Token；不能把角色存储在浏览器当授权。D:/项目/智能化/web/src/api/files.ts 复用客户端提供上传和鉴权下载，避免模板/知识/证据各写一套。类型按当前任务相关schema实现，优先复用既有类型；不为全合同提前创建未用空服务。

## 3 数据落库规范

内部主键采用UUID；时间使用带时区时间戳并以UTC保存；revision为非负整数。字符串长度和枚举取合同，数据库关键字段加相同约束；JSONB只存有schema的语义内容、工具摘要或规则，不把所有权限和状态放进任意JSON。

| 表或逻辑对象 | 权威业务字段来自 | 数据库额外要求 |
|---|---|---|
| users、sessions、user_roles | User；SessionResponse的会话信息由服务端生成 | account规范化唯一；密码哈希/外部身份不出DTO；会话可撤销；角色分配审计 |
| projects、project_members | Project、ProjectMember | ownerId外键；项目与owner成员同事务；成员(projectId,userId)唯一；ownerName由关联查询，不维护第二个名字 |
| facts、fact_revisions | Fact、FactCreate/Patch | key在项目和范围内稳定；已确认历史不可原地覆盖；来源/决定与修订绑定 |
| template_packages、template_versions | Template、TemplateVersion | 同模板version唯一；发布版不可改；源文件哈希与映射/Skill/规则绑定；修改草稿即失效旧验证 |
| documents、block_revisions | Document、Block、BlockRevision | 文档绑定模板版本；块key在文档中唯一；当前稿/批准稿指针独立；候选不自动切指针 |
| knowledge_bases、kb_access、project_kb_bindings | KnowledgeBase、KnowledgeAccess、KnowledgeBinding | 作用域非空且一致；绑定不扩大权限；库访问主体受用户状态影响 |
| sources、source_versions、source_chunks | SourceVersion和Citation定位 | 源文件版本与解析generation分开；发布指针原子切换；片段保留标题/表格/定位和授权来源 |
| files | FileInfo | 存储键与项目/库归属在服务端；不返回宿主路径；临时/正式状态与数据库引用一致 |
| jobs、job_steps、job_events | Job、JobEvent | actor/范围/输入快照；租约、世代、检查点；(jobId,sequence)唯一；外部动作意图先落库 |
| conversations、messages | Conversation、Message | 默认本人可见；项目或库范围固定；业务结果按项目授权，不自动分享私人会话 |
| reviews、relations、impacts | Review、Relation、Impact | 批准绑定具体修订；语义引用可双向，生成依赖无环；影响记录幂等去重 |
| test_cases、test_case_revisions、test_runs、test_steps | TestCase、TestRun、TestStep | 每次运行固定用例/软件/环境版本；失败历史不改；断言与执行错误分开 |
| evidence | Evidence | 原图与派生关系；真实工具/人工导入明确标记；跨项目不能自动复用成新证据 |
| model_profiles、environments、settings | ModelProfile、EnvironmentProfile、SystemSettings | 秘密由secretRef或批准秘密存储持有；公开DTO无秘密；配置修订不可冒用旧验证 |
| delivery_baselines、delivery_items、audit_events | Delivery、AuditEvent | 发布清单冻结内容/规则/文件版本；审计只追加并限权；哈希不等于数字签名 |

列表total、可见名称、当前权限、canEdit、allowedActions为查询或权限判定结果，不保存成可以长期失真的权威值。必要索引至少包括项目/状态/时间、成员用户、文档块修订、来源世代、待领任务、事件顺序、引用反查。迁移应可在隔离空库和上一版本数据上执行并有回退说明。

## 4 事务与并发的精确边界

- 项目+初始owner一起提交；失败不得留下无负责人项目。
- 人工保存：比较Block.revision，写新内容修订，更新当前指针与revision，在同一事务完成。
- 模型输出：固定baseRevision和来源快照，写候选，不改当前指针。采用候选时再比较版本，失败返回409，原稿保留。
- 审核：检查被审修订仍是选择对象；批准只更新明确批准关系，不把未来草稿一起批准。
- 知识发布：完成新generation验证后才切发布指针；中途失败仍保留旧发布版本。
- Worker：短事务领取、释放后再调用外部模型/工具；提交结果核对当前lease/fencing，不在外部调用期间长期锁数据库。
- 非幂等浏览器操作：动作意图先记录；响应未知转needs_verification，不能凭幂等键或lease宣称外部动作恰好一次。
- 文件/Word：临时生成→校验→存正式文件→提交清单；部分失败不得把基线标published，孤儿文件按保留策略清理。

## 5 权限实现顺序

每个operationId的x-required-permissions只是动作能力，另需当前用户有效、对象所在项目/库授权、状态允许、来源权限；工具再加环境和批准范围。未知能力默认拒绝。前端菜单和按钮只作提示，不是安全边界。

第一版角色定义固定，GET /roles展示职责与可授范围；修改用户角色走setUserRoles，项目角色走setProjectMember。不建立自由策略编辑器。公共规则GET /system/rules是设置/模板/硬约束的只读汇总，修改回对应来源，不另造规则发布系统。

创建账号、模型连接、环境探测、执行工具和正式发布分别有自己的决策/授权门槛。认证首个管理员用受控引导，不提供公共注册或固定通用密码。scopeToken是短期绑定操作者/目标/动作/版本的范围凭据，不写普通日志，也不代替正常鉴权。

## 6 每类操作必须执行的业务检查

- Project：名称trim，周期两端都有值才比较；owner必须是可指派的有效账号。UI不把自由文本姓名当ownerId。
- Fact：模型或手工提出的值先候选；确认需要来源或明确人工决定；冲突不自动选取。
- Block：固定/事实直填/计算项拒绝自由正文写入；表格列数与每行单元格数一致；图片只引用有权Evidence，不接受路径或任意URL。
- Template：原件与已发布包不覆盖；AI块提示词/输出schema/来源规则均齐备；真实试填与目标办公环境确认后才发布。
- Source：上传原件不等于解析可用；仅当前已发布generation默认检索；页码无真实依据则不输出。
- Chat：qa不能自动提升为工具执行；项目外只能在明确授权公共库问答；来源撤权要检查旧正文而不只是隐藏链接。
- Test：预期不得仅照抄实现；失败/编译异常/工具错误分别记录；模型不能改产品代码或减弱断言。
- Capture：版本、角色和步骤对应；脱敏或裁剪保留原图关系；手册成功路径不冒充完整测试。
- Export：固定输入、不重新调用模型或跑测试；正式报告可如实包含失败；旧基线不可变。

上传限制由已批准settings返回；按purpose设不同格式白名单，source与模板规则文件不能混为同一个通用解析器。文件大小、类型、压缩展开、外部资源、路径和宏执行均需服务端限制；未配置不得不受限接收。不把任意配置文件当可执行脚本。

## 7 模板/Skill如何直接实施

首版不建设浏览器里的Word编辑器。模板管理员在副本中完成标记并提交模板文件、Skill和规则文件；UI展示解析后的中文块名称、依赖、输入与验证状态。字段内部key由包管理，不让普通用户填写编号。

已提供 [单块任务示例](D:/项目/智能化/docs/执行规格/fixtures/block-contract.example.json)：输入事实、专属提示词、ModelCandidateOutput输出合同、正常/缺材料结果与程序检查。它不是可生产使用的模板包，没有真实Word位置与样式批准，不能发布。

DEV08应将真实模板的每个AI块按同类结构定义：稳定内部key、中文title、原Word槽位、输入/依赖、提示词、内容schema、工具白名单、缺失行为、校验、实际样例。DEV13按这些规则执行单Agent循环；不是让模型同时决定标题、样式、工具权限和所有章节。
