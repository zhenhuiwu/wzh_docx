# 知识库 Agent 与文档执行实现

版本 v0.2 评审稿  日期 2026年9月27日

## 一 共用原则

知识库提供可追溯材料，项目事实提供已确认约束，Agent 在受控上下文中多轮完成任务，工具提供实际执行证据，模板引擎生成交付文件。五者不能合并成一次“把所有资料和模板发给模型”的请求。

程序能强制的规则包括权限、对象范围、输出结构、版本、编号计算与执行预算；事实和长篇语义质量仍需来源核对与人工审核。结构化输出不等于语义真实，引用存在不等于引用内容必然支持这句话。

候选修订不等于当前工作稿，任务完成也不等于候选已采用或文档已批准。采用、取消中、批量阻塞及来源权限叠加的统一建议见 [开发契约与遗漏补充](D:/项目/智能化/docs/完整开发方案/08-开发契约与遗漏补充.md)，实现时需与实际schema一起冻结。

## 二 知识库实现流水线

### 2.1 上传和原件保存

1. 在接收前验证用户对目标库的写权限、格式、大小和数量预算。
2. 上传到临时区，按真实内容核验类型、计算哈希，并检查是否存在可用的同库版本。
3. 文件与资料记录建立关联后提交为已上传；上传失败不形成可检索材料，孤儿临时文件延迟清理。
4. 建立解析 Job，立刻返回资料状态，页面逐个文件显示排队、进度或失败。

默认不允许从任意 URL 拉取资料。后续 URL 导入须有域名、网络、重定向与凭据隔离控制；禁止成为访问内网管理地址的通道。原件只读保存，解析不执行宏，不加载文档外部图片或对象。

去重是存储和版本辅助，不是权限机制。只能在当前授权范围内提示重复，不能通过哈希命中告知用户其他项目拥有某个文件。

### 2.2 解析、定位与分块

首版解析 DOCX、文字 PDF、TXT、Markdown。DOCX 保留标题层级、段落、表格行列、列表及内嵌图片的关系；图片仅作为附件或待确认材料，不能没有视觉/OCR 能力却描述出不存在的内容。PDF 保存解析可确认的页码与文本区域；扫描件未 OCR 时标记待处理。没有稳定 Word 渲染时，以章节和段落定位，不猜 Word 页码。

切分优先遵循章节、段落、表格和列表等业务结构，而不是等字数截断。过长块再拆分并附父标题与少量必要上下文；表格片段重复携带表头，避免数值丢掉字段含义。初始块大小、重叠与抽取质量阈值通过中文、英文、混合代码和长表样例调整，不在模型信息未知时锁死最佳 token 数。

每个片段保存资料版本、解析世代、父级路径、内容摘要哈希、定位数据与文本。解析错误可能只影响部分页面：界面显示部分成功和缺失范围，正式发布需审核缺失是否可接受，不能把丢内容的文件标为完整成功。

### 2.3 发布、重建和更新

解析与索引写入新的 generation；完整校验后切换 published_generation，保证查询不混用一半新片段、一半旧片段。旧世代保留到历史引用和保留策略允许清理。

新文件内容是新资料版本；同一版本因解析器升级重建是新解析世代，二者分别追踪。重试只重做失败阶段，不重复创建逻辑资料版本。停用先从新检索排除，清除相关缓存，保留有权访问的历史引用。

### 2.4 检索首版与增强

首版：授权库与可用版本过滤 → 文档名/标题/术语与内容关键词匹配 → 合并去重 → 按来源相关性、匹配位置与项目范围排序 → 返回片段及引用。对中文使用真实语料验证，不能把默认英文分词效果当作中文方案；小规模可先以受限查询和标题/段落索引完成，再按评估决定中文分词或索引扩展。

增强条件：词汇差异导致的漏召回达到实际业务问题，并且公司有批准的 embedding 模型及资源。届时增加本地向量召回并与关键词结果融合，必要时配置本地 reranker。仍优先复用数据库或现有公司检索设施，不默认部署独立向量集群。

无论采取何种索引，都必须在候选召回前限制授权范围，在结果与原文读取时再次检查；不能先把未授权片段送给模型再删除引用。相似度只参与排序，不是事实可信度。权威已确认来源与一般历史资料的适用性由用户和规则决定，不以向量分数替代。

查询缓存键含用户或权限集合版本、项目、库、资料发布世代、检索配置与问题摘要。权限撤销或资料停用要使缓存失效；旧会话再次展示敏感来源时也要鉴权。

### 2.5 问答与引用

回答流程：解析问题 → 明确项目/公共库范围 → 检索 → 检查证据充分性 → 构造小范围上下文 → 生成回答和允许来源标识 → 校验来源存在与可见性 → 返回答案和引用。

引用在 UI 显示资料名、版本、章节或已确认页码；内部 source/chunk ID 不作为面向人的编号。模型只可从本次允许来源集合中引用，若无依据则明确未找到或需要补充。矛盾来源并列说明并请求负责人确认，不自行修改项目事实。

问答内容不会自动写入文档或事实表。用户选择“用于本块”时创建候选草稿并附原来源；确认公共事实时进入专门确认流程。资料衍生内容保留其访问边界，不能通过“总结一下”绕过保密权限；需要推广到公司公共库必须显式审核脱敏。

## 三 Agent 工作记忆和调用合同

### 3.1 记忆结构

- 共享事实层：项目、软件、术语、已确认需求/设计决定；版本化保存。
- 资料层：源文件与片段索引、证据及其版本；不复制整份到每条消息。
- 已确认内容层：可引用块、关系、人工决定和交付基线。
- 当前任务层：计划范围、已执行步骤、临时草稿、问题和检查点；未确认内容有明确标签。
- 会话层：用户请求与历史交流；摘要仅帮助查找，不覆盖原始事实与证据。

同一个 Agent 从这些层按任务重建上下文。切换项目创建新的作用域；使用相同模型不代表共享所有项目会话。用户角色或材料权限变化后下一轮重新鉴权，不能继续使用旧上下文里已经撤销的材料执行新动作。

### 3.2 每轮输入合同

输入含 taskId、projectScope、mode、targetBlock/targetStep、expectedRevision、模板/Skill/提示词版本、允许事实和资料集合、输入版本快照、输出 schema、allowedTools、预算与停止条件。由服务端生成，模型不得修改任务范围。

输出允许四类之一：指定块候选内容、受限工具请求、材料/冲突问题、当前小任务完成说明。每类有明确字段 schema，不接受任意附加字段或整篇自由 Markdown 直接写 Word。模型可以建议下一步，但真正调度由程序检查依赖与批准范围。

上下文优先级：系统安全规则 → 项目已确认约束 → 文档 Skill → 块级提示词 → 当前任务 → 不可信来源。资料内容被明确标为证据数据。公共硬约束不能被块提示词覆盖。

### 3.3 能力探测与适配

开工时用无业务机密样例验证：普通文本、中文结构化字段、缺字段停止、工具动作、上下文边界、引用选择、流式返回、取消、超时、限流和错误类型。只接受供应商实际支持的协议，不凭接口路径名推断能力。

原生工具调用可用时接入受限工具；不可用时可尝试结构化动作输出加服务端校验；仍不可靠就仅开启问答/草稿模式，并允许人工触发工具。视觉模型不是普通 Web DOM 操作的必然前提，但纯文本模型不能据截图判断颜色、遮挡等视觉问题；这些必须通过程序检查、指定视觉能力或人工确认。

不要为让本地模型看起来成功而放宽 schema、允许任意脚本或无限增加重试。设置单轮时限、输出预算、总轮次、工具步骤数和修正次数，超限后保留结果与原因。

### 3.4 执行循环

领取当前步骤并核对版本 → 准备上下文 → 调模型 → 解析结构 → 权限/范围/来源校验 → 需要工具则执行已授权动作 → 验证工具结果 → 保存检查点和候选业务内容 → 发布可见事件 → 选择下一个就绪步骤。

一个块可跨多轮检查材料、起草、局部修订；一轮只保存一个目标块的修订。一个工具阶段可填一组有边界的表单字段，不要求每次按键都调模型，但关键页面变化后要重新观察。文档级批量任务只是这些步骤的集合。

最终一致性检查返回问题及受影响块，不输出完整文档替换前面的确认内容。程序直填项目名、数值、真实结果、图号和表号，不额外要求模型重述所有可计算字段。

## 四 状态、恢复和人工协同

### 4.1 分开保存四种状态

| 对象 | 状态维度 |
|---|---|
| 草稿与审核 | 草稿、待审、批准、退回；另有当前有效/上游变化/冲突 |
| 任务 | 排队、运行、等输入、暂停请求、暂停、取消请求、待核实、成功、失败、已取消 |
| 测试 | 执行完成性与通过/失败/阻塞/跳过/待人工确认分开 |
| 资料 | 上传、解析、待处理、待发布、已发布、失败、停用 |

不能用一个通用“完成”同时表示模型已回复、文档已审批、测试通过和资料可检索。

### 4.2 中断与失败处理

| 场景 | 处理 |
|---|---|
| 模型超时且没有外部动作 | 有限重试，保留尝试；幂等保存草稿 |
| 非法字段或额外章节 | 拒绝写入，可有限修正；不修改其他块 |
| 输入版本已改变 | 保存候选并标冲突，重新核对后再采用 |
| 服务重启或租约过期 | 读取检查点与外部动作记录，防旧 worker 提交；未知副作用先核实 |
| 上传或解析失败 | 保留原件和明确阶段，重试不覆盖已发布版本 |
| 点击提交后网络异常 | 标记结果待核实，用唯一测试数据查找；未核实不重放 |
| 用户请求暂停 | 先暂停中，停在安全边界后暂停；不谎称已撤销外部动作 |
| 人工接管浏览器 | 排他控制权，Agent 停稳；归还后重新观察环境 |
| 人员停用或授权撤销 | 后续读写/步骤被拒；已发出不可取消请求保留待核实记录 |

UI 修改候选必须带修订号，默认不自动采用。批准引用资料有新版本时形成复核事项，旧稿和旧执行记录保留。用户要求“重新生成”要区分文字生成、测试重跑、重新采集和重新导出四个动作。

## 五 工具实现

### 5.1 单元测试运行器

输入为批准代码快照、目标函数、用例版本、依赖环境、执行命令模板和资源预算。代码副本隔离，源产品代码只读；只允许在批准测试目录增加或修改测试。依赖固定到公司批准源，模型不能临时安装任意软件。

实际执行保存标准输出、错误输出、退出状态、报告文件、断言结果、构建标识与环境快照。每种语言先选一个已有框架适配其结果格式，不通过日志里是否出现“passed”字符串推断全部成功。当前代码语言未确认，不能默认已支持所有 Python/Java/C++/.NET 项目。

预期来源、mock 范围、随机/时间控制、外部服务和测试数据均需记录。覆盖率若启用只作为一个质量指标，不证明逻辑正确；mock 完全部依赖也不代表集成行为已验证。

清理临时目录必须限制在本次任务工作区；资源耗尽、依赖缺失和编译失败分开记录。不得为了跑通而使用宿主管理员、生产凭据或开放任意网络。

### 5.2 浏览器运行器

任务固定目标域名、环境、账号角色、浏览器版本、视口、软件构建及数据范围。客户端只能引用批准凭据，不传明文到聊天。登录状态可复用但需正确隔离和保护，其内容可能足以冒用会话。[T08]

按语义角色、标签或稳定测试属性定位；定位多个候选、控件不可操作或页面意外跳转时停止。安全动作集与后端参数 schema 绑定，禁止让模型输入任意 JavaScript 以绕过工具限制。

功能检查使用可观察断言，例如文本、字段值、记录状态与导航目标。Playwright 提供自动等待/重试的断言，但仍需正确的预期和合理时限；截图存在并不构成通过。[T09] 涉及持久化的用例可经允许的刷新或查询确认，不随意访问产品数据库。

浏览器 Context 隔离会话不隔离后台业务数据；使用测试账户、独立数据前缀、可重置环境或批准清理，防止不同运行互相影响。每次失败、重试和清理有独立记录，不能只显示最终成功。

### 5.3 截图与手册素材

截图时机由用例或手册块要求决定：操作入口、关键输入、结果、错误现场；不默认每个动作一张图。记录页面与时间、角色、软件版本、视口、关联步骤及用途。

截图展示与取证要求可不同：原图受限制保存，文档图可裁剪、遮挡敏感区域或加箭头序号，并记录派生关系。脱敏检查不只针对图片，trace、网络日志和说明文字也可能泄密。临时凭据、cookie 和敏感业务数据不得进入普通下载包。

复用测试截图编手册须满足版本、角色、内容与可读性，不拿旧版本或其他项目结果凑材料。安装和恢复等未实际验证的规程必须明确来源，不标为已验证结果。

## 六 模板编译和 Word 导出

### 6.1 模板准备

保留原件 → 识别固定文字、指导说明和重复区 → 人工确认映射 → 在副本中标记占位符 → 定义字段和块 schema → 绑定 Skill/提示词 → 确认适用性 → 试填与目标环境校验 → 发布模板包。

原件中的指导文字不能全部当正文保留，也不能自动删光。签审、固定声明和特殊栏目先由模板负责人确认。模板字段分程序直填、AI 候选、人填与程序计算，不向用户暴露内部 key。

原始模板含文档编号栏时，必须明确自动填充的业务规则、批准裁剪或其他验收处理；在规则未定前标为待适配，禁止增加编号 UI 或用数据库 ID 将就填入。

### 6.2 确定性渲染

导出先锁定文档块、事实、证据、规则与样式版本；将结构化语义转换为批准样式，填入模板，而不是让模型自由输出 OOXML。图片按证据 ID 定位文件，尺寸由规则决定，图题与引用由程序计算。

docxtpl 的普通标签存在 run/段落限制，跨段落、表格行需相应结构标签；富文本可能改变字符样式。模板验证需覆盖这些边界，不能只做原始字符串替换。[T07]

固定样式、分节、页眉页脚、表格和关系需保留；重复区的书签、关系标识、编号和引用要正确重建。对特殊字符转义，不允许候选正文塞入模板表达式并二次执行。

填充后检查必填字段、残留标签、缺图、无效书签和引用。随后按批准的引擎更新目录、页码与布局并生成预览。跨文档优先以名称/章节/版本引用；必须页码引用时在完整渲染后解析，必要时再更新，不让 AI 猜页数。

### 6.3 输出环境和审批

目标 Word/WPS 版本、字体和合法授权需确认；不同引擎的结果不能未经样例比较视为等价。无法自动达到目标标准时保留明确的指定办公环境人工检查关口。

不要默认在无人值守服务器使用 Word COM。微软对常规服务端 Office 自动化有不推荐和不支持说明；任何例外部署形式都需另核支持范围和许可。[T10]

正式发布时锁定清单、文件哈希、审核者、模板/Skill/提示词及内容版本。模型随机性不影响已经确认内容的版本绑定；相同业务输入可以重复导出，但不承诺 ZIP 时间戳等字节级完全一致。文件哈希用来标识本次文件，不自动构成数字签名。

## 七 回归样例与效果评估

固定样例包括：正常资料、缺资料、冲突事实、长中文、嵌套重复表、特殊字符、多截图、解析失败、权限撤销、页面提交超时、模型错误结构、代码无法构建和真实断言失败。

知识检索评估检查指定问题能否找到正确授权来源、引用是否支持答案、无答案时是否拒绝编造；不要以回答流畅评价检索质量。Agent 评估看越界写入、证据误用、人工修改覆盖与停机是否正确。文档评估看真实人工总耗时、事实错误、格式返工和审核通过情况。

每次模型、模板、提示词、解析器或测试适配升级都跑相关样例，记录原配置和新配置；只有验证通过才推广到新任务。历史交付继续引用旧版本，不自动被一次“系统升级”改写。
