## 一 交付策略

保留现有 Vue3 页面与设计令牌，用真实服务逐步替换本地原型。先完成跨六模块的最小真实闭环，再加入经验证的函数测试与浏览器执行，最后扩大模板和环境覆盖。不把“六个菜单都能打开”作为六模块开发完成。

每个工作包交付内容、接口、数据迁移、错误处理、授权与验收记录；不能先做完全部 UI 再考虑后台数据和权限。所有新增前端必须遵守仓库固定入口和截图规则。

## 二 里程碑与出口

| 阶段 | 主要成果 | 必须满足的出口 |
|---|---|---|
| G0 关键验证 | 模型调用样例、真实模板试填、选定测试语言、可操作 Web 环境、权限与部署决策 | 至少一个块多轮生成可校验；代表模板在目标办公环境合格；自动执行边界明确 |
| G1 真实业务底座 | 登录/会话、用户和项目成员、项目资料、基础系统配置、文件与审计、持久任务 | 无伪登录和运行时假数据；项目隔离；服务重启任务可诊断恢复 |
| G2 六模块编制闭环 | 模板包发布、知识资料上传解析检索、助手有来源问答和分块编写、工作台待办、审核和 Word 导出 | 一份真实文档从资料到交付完成，六模块状态一致，手工证据可导入 |
| G3 自动测试与截图 | 一种语言的函数测试、一个 Web 场景的功能测试/手册采集、接管与异常处理 | 真失败和真截图可追溯，未知副作用不重放，模型不擅改业务代码 |
| G4 扩展与上线 | 优先模板批量适配、关系影响强化、离线包、备份恢复、安全和视觉回归 | 固定验收集通过、限制公开、恢复演练完成、职责签署 |

G0 可以先做小型验证而不实现全部管理页面；G1 的权限、文件版本和任务持久化不能推迟到 G4。G3 选最急场景先接通，不强迫两类工具同时上线。20 份模板的适配数量以实际交付清单为准，未适配必须在 UI 标明。

| D:/项目/智能化/web/src/styles/base.css | 已有单一令牌 | 保留，集中修正发现的问题；不要组件内加新色/字号/圆角 |

迁移步骤：备份现有真实用户输入 → 由负责人区分演示和需要保留的数据 → 导入预览与字段校验 → 人工匹配负责人/用户 → 写入测试环境 → 比对数量与名称 → 批准正式切换 → 保留回退窗口。浏览器旧数据不静默删除，不因迁移失败丢弃；切换完成前也不双写本地与服务端制造两套权威数据。

数据库升级采用版本化迁移和兼容回退计划；不可逆操作先备份并记录。新服务故障时回到维护或只读模式，不回到绕过认证的原型登录。模板原件和既有正式交付不参与覆盖式迁移。

## 五 测试分层与环境

单元测试检查字段规则、状态转换、权限范围、引用和模板映射等纯逻辑。接口集成测试使用隔离数据库、文件目录和测试身份，覆盖事务与冲突。工具适配测试使用批准代码样例和独立测试 Web 应用。端到端测试走真实 UI，不用只调用 API 代替按钮行为。

Agent 回归既需要固定假模型响应验证安全门禁，也需要真实本地模型验证实际可用性；两者报告分开。受控模拟可以证明程序能拒绝越界，不能证明模型生成质量。测试环境不得发真实付款、通知或生产审批。

现有前端 build 脚本含类型检查和 Vite 构建，后续可执行：

~~~text
npm --prefix D:/项目/智能化/web run build
~~~

这只是构建检查，不能代替 UI 截图测试。后端与 E2E 的执行命令要在相应工程实际建立后确定，不能把尚不存在的 test 脚本写为已经通过。

## 六 固定 UI 验收协议

每次修改任意前端后都打开 http://localhost:5173，按真实交互执行并保存截图，实际查看图片。至少覆盖 375、768、1440 宽度，并补充 1280 布局检查。先设计 375，再扩展到 1280；不能因为 1440 正常就忽略手机布局。

每个改动页面应覆盖正常、加载、空和错误；表单有 label、字段错误、disabled 与提交中。长文字、长文件名、中文输入法、无权限、版本冲突、超时等按页面风险选择样例。

查询点按钮或回车后真正提交筛选，分页确认结果和总数，重置恢复查询状态。修改/删除/发布等动作要看到真实状态变化和失败恢复。对齐、溢出、按钮可点区域、对比度、焦点环都要看截图和实际操作，不仅检查 DOM。

不允许通过 overflow-x:hidden 裁掉内容后声称无溢出；被遮住的按钮或文字同样不合格。对比度按真实背景、文字和状态检查，普通文字参考至少 4.5:1，大字 3:1；仅列出颜色变量不能证明已达标。[T12] 若令牌本身不合格，应提出统一修改并回归，而非每个组件偷加颜色。

截图按日期/页面/宽度/状态命名，关联测试操作与结果。报告明确哪些图片已人工查看、哪些失败待修；不能写“页面精致”来替代证据。本次纯设计未修改前端，因此没有把未执行的截图测试标为通过。

## 八 上线与回退清单

- 决策清单中模型、代码、浏览器、办公软件、安全边界有明确结果；不支持范围向用户可见。
- 所有上线模板带真实样例与发布记录，未适配模板不能假装已完成。
- 账号和初始管理员用安全引导流程建立，无默认通用密码；正式环境无演示项目和假成功返回。
- 原件、任务、文件和交付可恢复，日志和审计有保留策略、空间预警和负责人员。
- 凭据、cookie、源码和素材不入前端 bundle、浏览器本地持久缓存或公开下载目录。
- 必要依赖离线分发、浏览器与字体版本固定；许可证与公司安全基线经负责人核对。
- 回退测试包括数据库兼容、文件版本、任务暂停和降级只读，不能退回无真实认证原型。
- 负责人按本轮范围签署验收；未通过项作为已知限制，不用文字声明替代证据。
