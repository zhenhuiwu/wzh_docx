# 六模块业务与操作说明

版本 v0.2 评审稿  日期 2026年9月27日

## 一 产品范围与边界

本方案在原“项目文档智能编制”需求上，明确六个一级模块：工作台、项目管理、用户管理、系统管理、知识库、智能助手。六模块是业务入口，不是六个微服务，更不是六个 Agent。业务核心仍是一个项目的一组关联文档、确定的 Word 模板、模板配套 Skill、块级提示词和一个共享项目记忆的 Agent 多轮执行。

确认程度：六模块、单 Agent、分块任务、模板控制格式、函数级测试、前端测试和手册截图为用户已明确需求。本文的角色细分、字段、接口、流程顺序和技术选型为推荐实现基线，待评审后冻结。本地模型、测试语言、目标办公环境等尚未确认，不默认为已接通。

全局禁止展示或填写模板编号、文档编号；以名称、用途、所属项目、版本区分。内部 ID 只用于关联和授权。源文件名可能含编号，面向普通用户显示规范化名称；模板正文若强制有编号栏，须另行确认自动业务填充或裁剪规则，不增加编号表单，也不将数据库 ID 写入交付件。

## 二 六模块职责与互相调用

| 模块 | 用户主要任务 | 持有的权威数据 | 与其他模块的边界 |
|---|---|---|---|
| 工作台 | 找到自己的下一步工作并进入处理 | 待办指派、已读状态；其余聚合查询 | 不重复建项目、文档或审核状态 |
| 项目管理 | 建项目、维护事实与文档、组织测试、审核交付 | 项目、成员、事实、文档、测试、证据、发布基线 | 模板取系统已发布版本，资料关联知识库 |
| 用户管理 | 账号生命周期、全局角色、人员状态 | 用户、全局授权、会话管理 | 项目成员权限仍在项目中限定，禁止全局角色自动读取全部资料 |
| 系统管理 | 模板规则、模型环境、工具授权、运维与审计 | 模板包、Skill、模型配置、环境、策略、审计 | 管理配置不等于获得所有业务数据读取权 |
| 知识库 | 收集、整理、版本化检索可复用材料 | 资料文件、解析结果、来源定位、访问策略、索引 | 内容被检索不等于已确认事实或已执行证据 |
| 智能助手 | 基于授权上下文问答，发起和跟踪受控任务 | 会话、消息、任务请求和可观察运行日志 | 真正业务写入由项目服务校验；不直接操纵数据库或整份 Word |

跨模块的同一个待办、运行任务、证据或内容块采用同一个对象；工作台、项目页和助手只提供不同视图，状态不可各存一份。

## 三 工作台

### 3.1 页面组成

主视图是“我的待办”，辅以最近项目、最近文档和当前运行任务。可切换我的任务与有权限的项目范围。默认不放装饰性统计卡、虚构效率提升或全公司不可访问的数量。

待办类型：补资料、确认事实、复核上游变更、审核内容块、核实测试结果、处理截图缺口、解决导出错误。每项显示事项名称、项目名称、文档名称或功能名称、责任人、状态、更新时间与操作入口；不显示文档和模板编号。

### 3.2 交互规则

- 点“处理”直达具体块、资料缺口或执行步骤，不跳到文档顶部让人寻找。
- 按项目、类型、状态查询；筛选变化回第一页；翻页保留筛选与排序。刷新后保留非敏感筛选偏好。
- 运行任务显示当前目标、已完成步骤、等待原因和耗时；不以模型输出 token 百分比充当完成率。
- 待办只有在真实业务问题解决后关闭；“已读”不等于“已完成”。重复触发同一来源问题合并，而非不断产生提醒。
- 用户离开页面不取消后台任务；主动暂停和取消调用统一任务接口。

### 3.3 实现与验收

工作台聚合服务在权限过滤后查询任务、审核、影响清单和待补项；数量与明细来自同一查询口径。通知与待办分开：轻量通知告知变化，待办代表需要完成的动作。普通业务事件不触发外部短信或邮件，首版仅站内提示。

验收：用户只能看到授权项目的事项；待办能定位和解决；取消筛选和页码变化准确；无事项时说明可做什么；任何来源失败不伪装成零任务。

## 四 项目管理

### 4.1 项目列表和创建

项目名称、说明、所属单位、部门、负责人、计划周期为建议字段。负责人通过可选用户指定，不再用任意姓名文本代替账号关联；组织可先沿用受控字段，首版不建设复杂组织树。

创建向导：基本资料 → 选择适用模板集与文档 → 设置成员与角色 → 确认。只要求启动所需字段；模型、代码和测试账号可以后补。未适配模板可以登记为待准备文档，但不能启动生成。

项目状态建议保留未开始、进行中、已暂停、已完成，另设归档标志。项目暂停阻止新运行并按规则请求现有任务安全暂停，不影响只读访问；归档是历史保留，不等于删除。完成项目要求负责人确认，不以“所有草稿已有字”自动判定。

复制项目只复制明确选择的模板和非敏感配置；成员授权、凭据、截图和执行结果默认不复制。删除包含正式基线的项目走保留与审批流程；普通用户主要使用归档。

### 4.2 项目详情信息架构

| 子页 | 主要任务 |
|---|---|
| 概览 | 文档列表、待办与运行情况 |
| 文档 | 按块编写、资料核对、差异比较、预览 |
| 项目资料 | 已确认事实、术语、原始材料及知识库绑定 |
| 测试与采集 | 函数测试、功能测试、手册操作采集 |
| 关系与变更 | 需求—设计—测试—手册的引用和影响 |
| 审核与交付 | 审核、导出、冻结交付版本 |
| 成员与设置 | 项目角色、软件版本、环境绑定和适用性 |

项目与知识库的关系：项目可有自己的材料库，并绑定获准使用的公司公共库；链接库不复制所有原件，也不授予其他人源库访问权。正文正式使用的资料版本必须固定，不能在后台跟随“最新”悄悄改变。

### 4.3 文档实例及分块编辑

每份文档有名称、用途、模板包版本、负责人、内容状态、有效性状态和修订记录。同一模板可以创建多份用途不同的文档，例如函数测试报告、功能测试报告；名称在项目内的同一用途范围内去重，跨项目允许同名。

内容块类型：固定文本、事实直填、受控正文、表格、图片、重复区域、程序计算项。固定项和计算项只读；正文允许编辑；表格用结构化字段；重复块由已确认需求、函数、接口或用例生成实例，不由模型随意扩展。

操作：编写本块、保存草稿、比较差异、提交审核、查看来源、定位关联问题。批量生成是在用户确认的范围内逐块排队，不是一条提示词生成整篇。若某块缺资料，阻塞该块及其依赖，其他就绪块可按任务预算继续。

AI 新结果写为候选修订；人工已改内容不被覆盖。自动保存只保存草稿，不能自动签审。多个用户或 Agent 同时改同一块，通过预期修订号检测冲突，保留候选后让人比较合并。

### 4.4 事实、来源和跨文档关系

项目名、软件版本、术语、需求数值等来自事实记录，事实有候选、已确认和被替代版本；每次确认有来源或人工决定依据。需求或设计长文本不是全部都能抽成字段，语义一致性采用规则与人工检查，不承诺零遗漏。

引用使用稳定内部 ID 加修订号；UI 显示文档名称、章节名称、版本。引用关系可双向，生成依赖必须无环。修改上游生成影响清单，分类为文字复核、重新测试、重新截图、重新确认引用；不全篇自动替换，尤其不能替换旧执行数据。

### 4.5 单元测试

选择代码版本与函数 → 读取必要上下文 → 拟定用例及预期依据 → 确认 → 生成测试代码 → 受控运行 → 保存断言、日志和结果 → 编写对应文档块。函数用路径、限定名称和签名等内部信息定位，支持所选语言的重载规则。

预期不能只从实现反推；缺少需求或接口约定时待确认。不得擅改产品代码、减弱断言、安装未知依赖或无限重试。代码构建错误、测试脚本错误、断言失败和执行阻塞分别记录。并发或系统性能测试为独立范围，不能默认当所有函数测试的组成部分。

### 4.6 功能测试及用户手册采集

共用受控浏览器能力，但使用不同用例目标与 Skill。功能测试依据预期执行操作、断言和截图；手册按用户操作任务获取关键页面及步骤，再编写教学说明。手册采集成功不等于已经完成完整功能验证。

支持观察、定位、填写、点击、上传下载与截图的批准子集；不支持的控件或验证码允许人工接管或上传材料。每次任务绑定测试环境、账号角色、软件版本、数据和清理计划。浏览器会话隔离不能替代后端测试数据隔离。

提交结果未知时先核实，不直接重试；人工接管先让 Agent 停稳，归还后重新观察。截图需保存原图与裁剪、标注或脱敏派生关系。SUM 中安装、备份、恢复等必须从已确认资料取得，不通过几张页面截图编造。

### 4.7 审核、导出与交付

审核区显示本次差异、来源、自动检查和需确认项。批准对应具体修订；驳回附原因，不重置其他已批准内容。责任人自审是否允许由项目制度确认，高风险交付建议分离编审。

草稿可带明确标识导出；正式交付检查适用性、必填内容、引用、版本、证据和审批，再按模板生成。目录、长表格、图号、分页和目标办公环境另行验证。测试失败可以被如实写入可交付报告；软件上线批准与报告发布是不同事项。

交付包锁定内容、资料、模板、Skill、提示词和证据版本；后续修订创建新基线。外部改过的 Word 作为修订附件人工比对，首版不承诺自动双向回写。

## 五 用户管理

### 5.1 页面与账号生命周期

用户列表显示姓名、工号或登录账号、部门、全局角色、启用状态、最近登录；账号标识不属于被禁止的模板或文档编号。支持查询、分页、新增、修改资料、停用、重置凭据与撤销会话。

内网首版建议由有权管理员创建，无公开注册。全局登录账号唯一；姓名可重复。已有 SSO/LDAP 时先确认接入协议、账号映射和离职同步，未确认前不要假装已集成。

创建账号不能设置用户无法拥有的高权限；管理员敏感操作要求再次确认。重置密码发一次性短期凭据或批准的重置流程，管理员不能查看原密码；本人首次使用后更换，日志不记录明文秘密。是否强制多因素由公司制度确认。

停用撤销有效会话和后续任务授权，在步骤边界停止可暂停动作，并指派遗留待办；执行结果未知仍须核实，不能伪称动作已撤销。移交项目负责人和审核任务后才允许完成人员离任。最后一个有效管理员不可被直接停用或降权。

### 5.2 全局与项目权限分离

全局权限建议设用户管理、系统配置、模板维护、知识库维护、审计读取等能力集，UI 初期以少量固定角色组合呈现，不开发拖拽权限设计器。

项目角色为负责人、编写/测试人员、审核人员、只读成员。模板管理员负责模板规则，不自动审批项目事实。系统管理员管理平台，不自动获得所有保密项目的正文和聊天读取权；需要时通过明确授权或紧急授权流程记录理由和期限。

| 操作 | 项目负责人 | 编写/测试人员 | 审核人员 | 只读成员 |
|---|---|---|---|---|
| 查看授权项目 | 是 | 是 | 是 | 是 |
| 调整项目成员 | 是，受全局授权范围约束 | 否 | 否 | 否 |
| 编辑资料与草稿 | 是 | 是，限授权范围 | 默认否 | 否 |
| 确认公共事实 | 是或指定责任人 | 默认提交候选 | 可受委托 | 否 |
| 执行测试/采集 | 仍需工具授权 | 仍需工具授权 | 默认否 | 否 |
| 批准内容 | 按编审制度 | 默认否 | 是，限指派范围 | 否 |
| 发布交付 | 是且门禁通过 | 否 | 可审核，不默认发布 | 否 |

问答和检索权限等于用户当时可访问范围；聊天历史若包含已撤销项目内容，重新访问时仍要授权校验。权限变化不能只更新导航菜单而保留下载、搜索或后台工具漏洞。

## 六 系统管理

### 6.1 模板、Skill 与提示词

模板管理置于系统管理。按名称、类型、适用场景、版本和适配状态查询；源码 ID 和文档编号不做筛选项。20 份原件作为受保护资料保存，不覆盖。

模板包统一版本化：原 DOCX、副本字段映射、块结构、schema、文档 Skill、块提示词、允许工具、编写要求、校验规则及回归样例。草稿、验证中、待批准、已发布、已停用的状态分别展示；“数组非空”不能作为发布充分条件。

发布前校验字段覆盖、固定文字、嵌套重复区、样式、空值/长文/多图、编号与引用，且由指定办公环境验证。发布后不可原地修改，项目选择升级并处理映射变化。模板停用阻止新选用，旧项目按批准政策继续访问原版本。

Skill 与提示词编辑同一处维护，项目和助手只引用发布版本，不复制为各自一份隐藏配置。普通用户可看面向业务的编写要求，不必看提示词源码。

### 6.2 模型与检索配置

模型配置含显示名称、内网地址、协议、模型标识、能力测试结果、上下文和输出预算、超时、重试、启用状态及密钥引用。具体模型接口待确认；不假设“OpenAI兼容”必然实现相同工具能力。

保存与测试连接分开；测试只用无业务机密的固定样例，不将真实资料用于无提示诊断。密钥不可回显，普通用户不可随意设置模型或解析服务地址，以免数据外发。embedding 或 reranker 是可选配置，未配置不伪称语义检索已启用。

模型/提示词变更先用固定样例回归，任务固定使用启动时的配置版本。紧急停用阻止后续调用，已发出请求按可取消能力处理并记录。

### 6.3 执行环境与工具

登记代码运行环境、测试框架、依赖镜像或离线包、浏览器环境、目标域名、可用角色凭据、渲染环境、资源上限、数据清理与网络白名单。

任务只获所需工具。普通编写不能调用终端或删除页面数据；人工确认批准的是具体环境和动作范围，不是永久放开所有执行权限。生产默认禁用自动操作，确有需求需另行审批和专项方案。

首版允许用受控表单配置已有工具，不允许任意上传脚本或从 UI 执行自由 shell。模板与文档附件作为数据解析，不执行宏或跟随外部资源。

### 6.4 设置、审计与运维

基本设置、字典、组织字段、会话策略、工具预算、保留期、容量、备份和恢复记录集中管理。敏感策略变更需确认并保存旧版本；“恢复备份”不是普通立即按钮，必须维护窗口、预检和权限复核。

审计记录账号变更、授权、事实确认、规则发布、工具调用、审核与交付。记录操作者、对象名称与内部 ID、版本、时间、动作、结果及关联请求，不保存密码、cookie、完整隐私提示词或无必要业务全文。系统日志、运行证据、审批记录和聊天记录分开保留。

## 七 知识库

### 7.1 类型与资料生命周期

建议两类：公司公共知识库和项目知识库。公共不是全员公开，仍由授权组控制；私人临时资料首版作为个人会话附件，不另建复杂第三种知识系统。

库字段包括名称、说明、归属、维护人、读取和维护范围、启用状态。创建库后才能上传资料、绑定项目。创建同名文件不能默默覆盖，提示作为新版本或独立材料；相同哈希去重仅在当前有权范围内进行，不泄露其他项目是否拥有相同文件。

资料状态：已上传、解析中、待处理、待发布、已发布、失败、停用。发布后才进入默认检索；有意允许草稿检索时仅在明确工作模式和权限范围内，结果标明草稿。

### 7.2 页面与操作

库列表 → 库详情（资料/检索验证/权限与设置）→ 资料详情（原文/结构片段/版本/处理日志）。上传支持多个文件逐个显示状态和失败原因；取消不影响已成功项；不把上传完成等同于可检索。

首批格式建议 DOCX、可提取文字的 PDF、TXT、Markdown；扫描 PDF 在缺 OCR 时显示待处理；DOC、含宏、复杂表格、图纸等不静默转为空文本。具体解析器与格式需要样例验收。

查询支持名称、内容关键词、类型、来源范围和版本；命中展示材料名称、章节或已核实页码、摘录、版本及原文入口。不提供猜测页码。检索验证用于维护人判断查询和引用是否准确，不暴露无权片段或后台任意 SQL。

### 7.3 引用与删除规则

项目事实或文档引用的是资料版本及片段，不是库里不断变化的最新内容。新版本完成解析再原子发布，旧版保留满足历史引用。停用后从新检索排除，但对有权用户保留必要历史引用入口。

正式基线引用的素材不能普通删除；先检查影响、保留政策与审批。删除后及时移除索引和缓存，已生成内容若含敏感来源按权限和保留规则处理。原始证据只能在授权边界内共享，不把历史项目截图当公共示例自动传播。

知识库只提供候选依据。Agent 不得把相似项目的性能指标、架构或测试结果当成本项目事实；确认入口回到项目资料。

## 八 智能助手

### 8.1 同一个执行者的三种使用方式

- 问答：读取授权资料回答并引用来源，默认无业务写入权限。
- 编写：绑定项目、文档和目标块，通过专属 Skill 与提示词生成候选修订。
- 执行与采集：在批准范围调用函数测试或浏览器工具，产生运行记录与证据。

三者是同一个 Agent 的任务模式，不是三个 Agent。聊天是交互入口，任务状态持久化在服务端；关闭页面不丢任务，清空聊天不删除项目事实或测试记录。

### 8.2 会话交互

创建会话选择项目或明确的公共知识范围；展示当前范围、可用资料和模式。项目外问答无权写项目文档，跨项目请求要求明确选择和授权，不静默混合。切换项目默认新建会话，避免上一项目内容污染。

问答流式显示响应，结束后提供可点击来源；无资料应说明缺口，不能编假引用。来源点击再次鉴权。会话默认本人可见，生成的项目业务结果按项目权限共享；分享会话必须显式授权，不能因为同项目成员就暴露所有私人聊天。

从项目块进入助手自动绑定目标。复杂请求先展示任务范围、缺材料、允许动作及需确认事项，用户一次确认后系统逐轮推进。可以发起处理整份文档的任务集合，但每轮写入只有一个块，最终检查只产问题，不全文重写。

### 8.3 任务卡与人工控制

消息区展示任务卡：目标、当前步骤、已完成数量、等待原因、候选结果和入口。提供暂停、继续、取消、查看证据和接管（条件满足时）。任务修改范围要重新确认；用户随口说“继续”不自动批准新的危险动作。

等待输入时展示具体表单，例如缺的软件版本或截图，不只回复“资料不足”。结果写入失败显示保留的候选草稿。过程展示动作、工具结果和简短依据，不要求保存模型隐藏思维链。

重试保留每次记录；断线重连按事件序号补齐，不重复插入消息或重新执行操作。模型不可用时历史和项目资料仍可查看，任务明确失败或排队，不能永远显示“正在思考”。

## 九 典型跨模块完整流程

1. 用户管理员创建人员并授权；项目负责人创建项目和文档集。
2. 知识维护人上传已批准材料，发布可检索版本；项目关联资料并确认事实。
3. 系统管理员完成模板、Skill、模型与执行环境配置，但不替代业务负责人确认内容。
4. 工作台提示资料已就绪；用户从文档块启动助手，后台多轮生成并保存候选修订。
5. 有测试或截图缺口时进入对应任务，取得真实执行记录并关联回文档。
6. 上游变化形成影响清单，工作台指派复核；旧批准版不被覆盖。
7. 审核人查看差异和证据，负责人按门禁发布交付；知识库仅按明确授权归档可复用成果。

此流程允许纯人工补材料与手工编辑，不把任何模型或浏览器故障变成整个平台无法使用的单点。

## 十 首版与后续边界

首版应覆盖六模块最小真实闭环：真实认证与权限、项目与文档块、已发布模板包、授权材料检索、一个 Agent 多轮编写、人工证据导入、审核与 Word 交付。自动化测试/截图在受支持环境验证后接入，不能因此迟延权限和来源保存。

后续增强包括经验证的语义检索、更多代码语言、更多浏览器/桌面控件、自动影响识别和复杂文档图形。暂不承诺全自动标准认证、所有格式解析、任意界面自由操作、所有语言测试、自动双向 Word 同步或无人审批生产发布。
