## 一 结论与交付范围

系统定位为“项目文档编制、知识检索与测试取证工作台”。采用工作台、项目管理、用户管理、系统管理、知识库、智能助手六个一级模块，以同一套项目对象、权限、任务和版本关系串联。核心执行方式保持一个 Agent 共享项目记忆、分多轮完成小任务，不一次生成整套文档。

推荐保留当前 Vue3 原型并接入真实后台。首版采用模块化单体、PostgreSQL、内网文件存储、持久任务和受控工具，先验证本地模型与实际模板，再完成资料—内容块—审核—Word 交付闭环。单元测试、功能测试和手册截图作为受权限限制的执行任务接入，而不是另做三套独立应用。

本轮输出是从页面交互到数据、接口、执行、迁移和验收的完整设计建议，不是已经实现的软件。未修改业务源码、依赖或原始模板，未启动应用或声称截图验收完成。尚未确认的模型、测试语言、办公环境和组织规则单独列出，不默认为用户已批准。

交给另一 AI 开发时，先使用 [接手 AI 必读](D:/项目/智能化/docs/交接/00-接手AI必读.md) 和 [可复制启动提示词](D:/项目/智能化/docs/交接/02-接手启动提示词.md)。它们区分当前原型、规划能力和待批准事项，提供前端规则与阶段回报格式；仅是准备材料，不代表已派发开发或验收通过。

需要直接按规格实现时，使用 [AI直接执行入口](D:/项目/智能化/docs/执行规格/00-执行入口.md)。它把方案落实为21页实施规格、25张任务卡、机器可读接口合同和合成验收输入；都是设计目标而非已实现服务。

## 三 当前现状与保留范围

已实际检查前端数据层、路由、登录、页面、样式和工程配置。当前有 Vue3 页面框架，但项目、用户、模板、知识库等主要是浏览器本地存储；登录不是服务端认证；助手未接入模型；知识库尚无原件解析与检索链路。不能把这些原型能力计作正式功能完成。

保留页面布局、导航基础、有效表单/查询交互和 base.css 令牌，逐步用真实接口替换原型数据。当前运行时示例数据不能进入正式项目，模板原型“已发布”不能跳过真实 DOCX 验证，旧浏览器用户记录不能自动升级成平台权限。

固定约束：

- 当前前端地址为 http://localhost:5173，不静默换端口。
- 每次前端修改后在 375、768、1440 宽度截图并看图，另外检查 1280；先设计 375。
- Vue3 保持不变，组件在现有 components 目录；基础控件复用既有样式，统一换库只允许 Element Plus 且先批准。
- 颜色、字号、字体、间距和圆角只使用现有变量；不加第二套主题和控件。
- 所有 UI 不展示或填写模板/文档编号；名称加项目、用途、版本识别。
- 无装饰 Landing、假 KPI 和未接入的假成功结果。

## 四 六模块如何分工

| 模块 | 用户来这里完成什么 | 不应承担什么 |
|---|---|---|
| 工作台 | 找我的待办、阻塞事项、最近项目与运行任务 | 不再保存一套与项目脱节的完成状态 |
| 项目管理 | 管项目资料、文档块、测试证据、关系、审核和交付 | 不维护模型密钥，不让文档各自编造事实 |
| 用户管理 | 管账号、角色、启停、凭据与会话 | 不把前端菜单隐藏当权限，也不随意清掉历史责任记录 |
| 系统管理 | 管模板/Skill/提示词、模型、环境、策略、审计与运维 | 不默认可读全部保密项目，不成为任意脚本执行控制台 |
| 知识库 | 管原始资料、解析、版本、授权检索和引用 | 检索命中不自动成为项目已确认事实 |
| 智能助手 | 查资料、按块编写、发起并跟踪受控任务 | 不直接改数据库或整篇 Word，不绕过授权和审核 |

模板管理归系统管理，不另增第七个一级模块。测试与手册采集在项目内，与文档和证据直接关联；助手只是另一种入口，不复制第二套任务系统。

## 五 一条真实工作链

管理员配置可用模型、环境和模板包 → 创建用户和项目 → 选择适用文档 → 上传/引用知识资料 → 负责人确认公共事实 → 工作台提示就绪任务 → 同一个 Agent 逐块处理 → 缺证据时启动批准的测试或采集 → 候选稿与人工修改比较 → 审核 → 程序填充 Word → 目标办公环境检查 → 发布固定交付版本。

用户可以只发起一次整份文档任务；程序在后台多轮推进，并在缺资料、冲突、危险操作或关键确认处停下来。整篇检查只定位问题，不用最后一次全文润色破坏块级控制。

## 六 核心实现决策

### 6.1 架构

现有 Vue3 + 原生 API 调用；推荐 Python/FastAPI/SQLAlchemy/Alembic 后端与 PostgreSQL；任务状态写数据库，由一个逻辑 Agent 执行器调用公司模型。独立的解析、测试、浏览器和渲染工作进程是工具，不是多个 Agent。

首版不默认引入 Redis、消息总线、专用图数据库、独立向量集群或通用低代码编排器。规模和检索评估证明需要时再添加。组件库迁移和具体依赖版本由后续评审决定，现有 package.json 不在本次升级。

### 6.2 共享记忆

共享项目范围的已确认事实、材料索引、批准内容、决定和进度；当前任务草稿可作为带标签的工作上下文，但不得未经确认传播为事实。每轮按目标选择上下文，不不断拼接整个项目进聊天。

### 6.3 知识检索

原件与解析片段版本化，发布世代原子切换；先授权过滤再召回，来源读取再次鉴权。首版关键词/结构检索形成真实能力，本地 embedding 条件成熟后再增强语义召回。资料从引用进入事实需要确认，不能用其他项目相似材料填本项目结果。

### 6.4 安全与可靠性

真实服务端认证、全局能力与项目权限分离、敏感凭据不出服务端、代码与浏览器工具受控、任务检查点与有限重试、人工修改冲突检测。外部提交超时先核实，不承诺数据库事务能撤销已执行的页面动作。

### 6.5 Word 与证据

原模板提炼成版本化模板包，包含字段、块、Skill、提示词和样例。事实、测试数值和编号由程序处理；AI 只组织必要描述。模板内部业务编号栏的处理待确认，不增加任何编号 UI，也不填技术 ID。

真实执行记录与文档叙述分离；重写不重测，重测不擦旧失败。报告如实写失败仍可进入批准交付；报告交付与软件上线是不同门禁。所有交付引用锁定来源、内容、模板和证据版本。

## 七 最容易遗漏但已纳入的事项

- 用户停用后，旧会话、任务、缓存、文件和聊天都不能绕过权限撤销。
- 索引重建不能出现半旧半新资料，删除不能破坏既有正式引用。
- Agent 生成期间人工修改会产生修订冲突，不静默覆盖。
- 页面操作中断、服务重启、人工接管和重复点击有可恢复状态。
- 功能测试与手册采集共用工具但判定不同；截图不证明测试通过。
- 用户手册的备份/安装/恢复等需要资料，不能仅凭页面猜测。
- Word 成功生成文件不代表排版合格，目标办公软件与字体必须明确。
- 现有原型数据迁移不能继承假发布、假认证或自动演示项目。
- 模板/文档编号在所有界面不可见，旧模板要求冲突必须显式解决。

## 八 建议开发顺序

新增的 [开发顺序排期与交付标准](D:/项目/智能化/docs/完整开发方案/07-开发顺序排期与交付标准.md) 将以下路线展开为 S0—S8 和 M0—M4。参考排期仅按明确人员与试点范围假设安排，不是工期承诺，S0 后重新估算。

G0 证明模型、模板与真实测试环境可用；G1 建真实身份、项目、资料、文件和持久任务；G2 打通六模块的知识—编写—审核—Word 闭环；G3 接函数测试与浏览器采集；G4 扩展模板、关系能力并完成离线部署、恢复和安全验收。

每个阶段有工作包、依赖与验收出口，详见开发路线。未知模型、语言和办公环境时不编造总工期；先完成关键试验，再按实际适配范围估算。

开发优先确认：本地模型、后端部署约束、真实身份来源、首选测试语言、Web 登录方式、Word/WPS 验收环境以及单元/功能测试的文档映射。其余事项可先采用书面建议，批准后再冻结。

## 九 本轮核查和下一步

本轮只做代码与方案静态核查，不做运行验收。技术官方资料已核实，现有模板不作任何格式修改。方案交付后应先评审决策清单，再把 W01—W12 转为实际开发任务；未确认生产和测试授权前不启动真实自动操作。

建议从一个真实项目、一种模板块、一个函数和一个 Web 用户任务组成的小样例入手。成功标准是总人工耗时下降且事实、证据、格式和权限可靠，而不是六个模块摆出好看的空页面。
