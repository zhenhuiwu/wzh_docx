## 一 这份计划怎么使用

本文件把六模块方案转为可按阶段执行和验收的计划，补充明确开发顺序、依赖、参考排期、负责人、交付物和停止条件。它与 [开发路线迁移与验收](D:/项目/智能化/docs/完整开发方案/05-开发路线迁移与验收.md) 配套：原文件保留 G0—G4、W01—W12 和 A01—A48，本文件将它们落实到执行阶段 S0—S8，不再建立另一套互相矛盾的功能清单。

开发顺序不是按菜单从左到右开发。先证明高风险环节，再建设认证和数据底座，然后形成文档业务闭环，最后接自动测试与扩大覆盖。工作台、系统管理和界面验收随业务能力增量完成，不需要等待全部模块做完才联调。

本次仍只编写计划，不启动真实开发、测试或部署。下文所有交付标准都是待执行要求，不能看作当前项目已通过。

## 二 首次试点范围与估算前提

### 2.1 建议先交付的范围

- 六个一级模块均具有真实可用的基础功能，不是只完成页面或演示数据。
- 先选一个代表项目和公司优先使用的模板。建议候选为软件需求规格说明、软件设计说明、软件测试说明、软件测试报告、软件用户手册；最终清单与模板复杂度在 S0 确认。
- 单元测试首版支持一种批准的代码语言与现有测试框架。
- 功能测试和手册采集首版支持一个明确的 Web 测试环境及登录方式。
- 知识库首版支持已确认格式的原件管理、版本、权限、解析和可追溯检索；扫描 OCR、语义检索按样例验证决定是否纳入。
- Word 输出在指定 Word/WPS 版本和字体环境验收；不自动承诺所有 20 份模板一次适配完成。
- 不包含未明确批准的生产操作、任意语言/桌面软件自动化、复杂 SSO 改造、全自动 Word 双向同步或无限制工具执行。

测试与手册截图是最终试点目标的一部分，不能以早期文档版交付代替后续自动化承诺。确需延期时，变更试点版本的支持清单并经负责人确认；人工导入是降级通道，不伪装成自动化已完成。

### 2.2 参考排期的资源假设

为方便安排，下面提供一个建议的时间盒：1 名前端、2 名后端/执行工具开发、1 名测试验收人员，并有业务负责人、模板/Word 负责人和运维人员按阶段配合。允许一人兼任，但可投入时间不足时必须重新估算，不能直接沿用同一结束时间。

“第1周”从范围、人员、样例和开发授权齐备后的批准开工日计算，不默认2026年9月27日已经开工。计划按16周组织工作窗口，另预留2周风险缓冲，形成约16—18周的试点预算窗口。这是排期占位建议，不是经过人日测算的工期承诺；S0 结束后必须用模型、模板与环境验证结果重排并确认基线。

前提还包括测试账号和脱敏材料可及时提供、模型服务可用、业务与模板评审每周有固定窗口。等待第三方授权或采购等外部时间单列，不通过压缩测试和安全检查抵消延期。首次上线覆盖全部20份模板时，应另排适配工作量，不直接套用此窗口。

## 三 推荐开发顺序

~~~text
S0 关键输入和技术验证
       ↓
S1 真实认证与业务基础
       ↓
S2 项目、成员、事实、基础工作台
       ├─ S3 模板、Skill、块映射、确定性 Word 试填
       └─ S4 知识库上传、解析、授权检索
                    ↓
S5 单 Agent 多轮编写、块编辑、审核、交付闭环
       ├─ S6 函数级单元测试
       └─ S7 功能测试与手册截图
                    ↓
S8 全链路回归、扩展适配、部署和交接
~~~

图中表示业务联调的主要依赖，不意味着 S3 必须等 S2 所有次要页面做完：模板样例试填在 S0 就要验证，S1 的必要身份/文件接口完成后，可并行实现模板和知识服务，再接项目入口。

S6/S7 若资源只能串行，优先做业务最耗时且已验证环境的一项，再做另一项，重排时间。研发人员并行开发工具，不改变产品运行时只有一个逻辑 Agent 的要求。

## 七 通用交付标准

### 7.1 功能与数据

1. 正常路径与缺材料、冲突、拒绝授权、网络失败、服务重启等对应异常路径都要测试。
2. 数据由真实服务持久化；跨刷新、重启、重新登录可恢复。开发测试使用的 mock 或演示数据不得进入交付默认行为。
3. API 实际写入范围、预期修订号、项目关系、事实来源与审核版本要一致。业务界面结果与数据库/文件记录对应，不只以 HTTP 200 判断成功。
4. 同一任务重复提交不重复落库；外部副作用的未知结果先核实，不能承诺所有浏览器动作恰好一次。
5. 关键失败留证，不隐藏失败历史，不为了文档完整编造数据。

### 7.2 界面与交互硬门槛

- 修改前端必须在 http://localhost:5173 真实打开操作，至少在375、768、1440宽度截图并查看图片，补充1280布局检查。
- 每个变更页面验证加载、空、错误；每个表单有 label、错误文案、disabled 和提交中。
- 查询、分页、保存、取消、发布、上传等通过真实点击验证，筛选与总数一致，失败时保留输入；中文输入法不误触发送。
- 排版对齐、文字不溢出、控件不遮挡、焦点可见、颜色和背景可读。不得靠裁掉内容来掩盖溢出；截图错位或难读就继续改。
- 只使用既有 Vue3、控件和 CSS 令牌；换组件库仅在批准后统一 Element Plus。模板与文档编号不展示、不填写。
- 必须有截图文件、操作记录及实际看图的检查结论；构建通过或 DOM 文本正确不能替代视觉验收。

### 7.3 AI 和知识质量

模型验证与门禁验证分开：固定模拟响应证明程序能拒绝越界，真实本地模型样例证明实际可用性，不能相互替代。

冻结一套业务验收材料，至少覆盖可回答、无依据、来源冲突、未授权来源、恶意指令、错误结构和长内容。验收集中的引用必须存在、可见、可定位且支持回答；无依据时正确提示，所有安全负例必须被门禁拦截。此要求只代表冻结样例的验收结果，不承诺模型在无限输入下绝无错误。

不得把解析或检索分数当事实可信度，不得将他项目测试结果变成本项目证据。公共事实需要确认，新稿需要审核，模型配置升级要重跑相关样例。

### 7.4 测试与截图质量

单元测试必须保存代码/构建和用例版本、运行环境、断言及真实日志；函数级预期来源可检查。功能测试必须保存步骤、判断依据、实际结果、截图和环境；每次尝试可追溯。手册截图对应真实角色、软件版本和步骤，原图与脱敏/标注图关系明确。

验收既要有真实成功样例，也要有应失败样例、无法运行样例和中断样例。报告如实显示失败可以交付；软件是否允许上线另行审批。未经授权不能改产品代码、削弱断言或操作生产数据。

### 7.5 Word 质量

每个上线模板都必须有短文、长文、重复表格、多图、空可选项、缺必填项、特殊字符及编号/引用变化样例，覆盖其实际支持结构。

在指定办公软件和字体环境检查字体字号、标题、段落间距、页眉页脚、目录、图表、引用和分页；页面数量可以随内容变化，格式规则不能随模型变化。必填缺失、残留占位符、缺图、错误引用、指导文字误入正文或签批信息伪造均不能发布。

原模板中的编号栏政策需先确认；不新增编号输入界面，也不用技术 ID 填充。全套20份模板登记完成不等于20份都通过适配验收。

### 7.6 安全、运维和性能

必须验证跨项目、检索、消息、文件和工具的权限隔离；停用与权限撤销实际生效；凭据不进入日志、聊天、浏览器持久缓存或交付包。

服务重启后有检查点与可解释状态；备份恢复覆盖数据库与文件，并实际检查引用和交付文件。日志可定位问题但不泄密，磁盘/队列等故障有明确处理入口。

性能、并发与恢复指标不能用“很快”“支持多人”验收。S0 记录环境与规模假设，S5 在真实链路测量，S8 前由负责人冻结以下指标表；没有完成指标定义和测量，不称为性能验收通过：

| 指标 | 必须冻结的口径 |
|---|---|
| 页面及普通 API | 指定数据量、并发、冷/热条件、P95响应阈值与允许错误率 |
| 知识检索 | 语料大小、权限范围、固定问题集、召回/引用正确性与时延 |
| Agent | 模型/硬件、块类型和输入量、超时、总轮次预算与失败处理 |
| 执行工具 | 函数或浏览器样例、资源上限、超时/停止界限及清理要求 |
| Word 导出 | 指定模板、页/图/表规模、渲染环境和完成时限 |
| 恢复 | 可容忍数据损失窗口、恢复时间、备份频率、实测恢复记录 |

这些数值目前未提供，不能填造未经实测的吞吐与恢复承诺。若试点规模有限，明确只按该规模批准，不外推为全公司容量。

## 八 每次交付必须给出的材料

每个阶段应交一套可核对的材料，不只发截图或一句“已完成”。

| 类别 | 必交内容 |
|---|---|
| 版本与范围 | 源码版本/快照、变更清单、已支持与未支持功能、关联阶段和验收项 |
| 可运行软件 | 前后端构建物或可复现源码、锁定依赖、启动/停止说明、无秘密的配置示例 |
| 数据与升级 | 数据库迁移、文件目录约定、现有原型数据处理、备份及回退方法 |
| 接口与权限 | 实际 API 合同、角色/范围矩阵、关键错误与状态说明 |
| 模板与 AI | 本阶段发布模板包、Skill/提示词版本、模型配置版本、样例输入输出、来源与已知限制 |
| 工具与环境 | 支持的测试语言/框架、浏览器/登录方式、隔离与网络边界、真实执行记录 |
| 验收证据 | 自动/人工用例结果、实际截图、Word渲染与办公环境检查、恢复演练记录 |
| 使用与运维 | 对应版本的用户操作说明、安装升级/回退/排错手册、备份和维护责任 |
| 问题与批准 | 未关闭问题、影响、处理人、计划、允许带入的理由，以及真实责任人的验收决定 |

开发阶段没有涉及的类别可注明“不适用于此阶段”并说明原因；最终承诺范围内的材料不能用空文件或“待补”替代。密码、密钥和真实认证状态不随普通包分发，按批准的独立渠道配置。

## 九 阶段验收与缺陷处理

统一流程：开发自检 → 测试复核 → 业务和模板责任人验收 → 缺陷修复 → 回归 → 保存证据与决定 → 进入下一里程碑。开发者不能凭自己的“运行成功”代替业务签审。

建议缺陷等级：

- P0：越权/秘密泄漏、数据损坏或丢失、未经授权的危险操作等；立即阻止相关发布和继续执行。
- P1：承诺的核心流程不可用、真实结果被错误改写、无法恢复、正式输出关键内容/格式错误等；交付前必须修复。
- P2/P3：不违反安全、数据、真实性与固定 UI 门槛的非关键问题，可由责任人明确影响、临时方法和修复计划后决定是否带入。不能把溢出、不可见焦点、缺必要状态或假通过降级为“美化问题”绕过要求。

本阶段范围内所有强制验收项必须通过，P0/P1必须清零；未承诺项可记录不适用，但必须说明范围依据并由负责人确认。不能把本来承诺的自动测试临时改成不适用来宣称完整完成。

验收记录至少包含：阶段、软件/配置版本、环境、用例标识、输入、预期、实际结果、证据位置、执行人、审核人、时间、通过/失败/不适用及原因。系统只记录真实人员决定，不自动生成批准签名。

本轮补充的状态/候选采用合同和B01—B08验收场景见 [开发契约与遗漏补充](D:/项目/智能化/docs/完整开发方案/08-开发契约与遗漏补充.md)。S0须登记独立确认的样例包，相关实现开始前冻结实际接口字段与状态，不能只用示意端点联调。

## 十 周计划与范围变更机制

每周开始确定本周目标、依赖和可演示成果；每周末用真实环境演示、回顾缺陷和更新风险。任务按“前端交互＋接口＋数据＋权限＋异常＋测试＋证据”切成纵向小项，不按“先把全部页面画完”拆工作。

每个工作项模板：用户场景、输入/前置、涉及对象/页面、接口合同、完成标准、验收用例、交付文件、负责人、依赖、风险、实际结果。每项只承诺一个可以独立验收的结果，未接入要明确禁用。

新增语言、模板类型、复杂控件、SSO或输出格式时，登记变更范围、依赖、工作量和验收影响，由负责人选择延期、替换同等范围或新增里程碑。不默默塞入既有时间窗口，也不因赶日期删掉必要审核、隔离、截图和恢复检查。

S8 后若需要继续适配其余模板，使用同样的模板回归标准逐份发布。实际运营维护时段、缺陷响应和支持职责另行约定，不把“交付完成”等同于无限期无范围维护。

## 十一 现在可以开始与必须等待的内容

现在可以准备：整理需求与样例清单、确认接口/数据合同、设计验收数据、清点已有原型和模板、安排负责人。得到后端选型批准后可以进入 S1 基础开发，不必等所有模板全部提炼完成。

必须先确认才能实际执行：公司模型接入、被测代码/语言环境、测试地址与账号/数据、工具操作权限、Word/WPS验收环境、模板编号栏政策、首批交付文档清单。细项见 [决策清单](D:/项目/智能化/docs/完整开发方案/06-决策清单与技术依据.md)。

最先完成的业务目标不是“六个菜单都齐”，而是“一份真实项目文档从资料、逐块生成、人工确认到合格 Word 的可追溯闭环”。随后将真实函数测试和界面截图接入这一闭环，再扩大覆盖。
