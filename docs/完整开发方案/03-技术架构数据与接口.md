# 技术架构数据与接口

版本 v0.2 评审稿  日期 2026年9月27日

## 一 当前仓库事实与目标

本次只读代码检查发现：前端位于 D:/项目/智能化/web，采用 Vue 3、TypeScript、Vite、Vue Router；端口配置为 5173 且 strictPort 已开启。已有项目、模板、用户、设置、知识库和助手等页面。项目、模板、用户、知识库等主要存储于 localStorage，登录仅校验输入非空后计时写入 sessionStorage；助手返回尚未接入提示。本次检查范围内未发现真实 API 调用或后端工程。

因此现状是可复用的交互原型，不是真实认证、多用户数据库、知识解析或 Agent 执行系统。本方案只制定迁移与实现，不宣称原型已上线安全可用，也未进行浏览器视觉验收。

## 二 总体结构及选型

~~~text
现有 Vue3 工作台：固定本地入口 http://localhost:5173
     │ 同源 /api/v1 代理，JSON/文件/事件流
     ▼
应用后端：身份鉴权 + 六模块业务服务 + 审计
     ├─ PostgreSQL：业务对象、修订、关系、任务和事件
     ├─ 内网文件目录：原件、日志、截图、渲染件、交付包
     └─ 持久化任务调度：一个逻辑 Agent 多轮执行器
            ├─ 公司本地模型（配置版本固定）
            ├─ 解析/检索任务（程序工具，不是 Agent）
            ├─ 受控函数测试运行器
            ├─ 受控浏览器运行器
            └─ Word 填充及渲染检查任务
~~~

推荐后端 Python、FastAPI、SQLAlchemy、Alembic、PostgreSQL。文件存储首版用带访问控制的服务端数据目录；公司已有对象存储时复用，不默认额外部署一套。浏览器用 Playwright，模板候选 docxtpl，具体受支持版本由样例测试冻结。上述新增后端库为提案，不表示已经安装。

前端沿用当前框架、路由、布局、基础样式和成熟交互，不重建 React 工程。API 采用原生 fetch 与现有组合式函数组织，首版不必仅为请求引入 Axios 或新的全局状态库。需要完整组件库时只允许统一采用 Element Plus，并集中映射现有 CSS 变量；官方支持主题变量配置，但需要真实控件适配与截图验证。[T11]

应用服务、后台任务进程和隔离工具使用同一代码库的不同入口；不用六套服务、消息总线或自主 Agent。首次实施以一个逻辑模型执行队列开始，未来可按项目隔离提高吞吐，但不得把同一个项目的事实无序并发更新。

## 三 代码组织建议

以下均为计划新增或改造位置，不是已存在后端：

- D:/项目/智能化/web/src/api：请求、错误、身份和各业务接口。
- D:/项目/智能化/web/src/views：沿用页面，按复杂度拆项目子页面。
- D:/项目/智能化/web/src/components：只放已有导航与确有复用的业务展示，例如来源列表、任务状态、版本差异；不手写另一套 Button/Input/Dialog。
- D:/项目/智能化/web/src/styles/base.css：唯一设计令牌来源；主题桥接集中维护。
- D:/项目/智能化/server/app：应用入口、业务模块、模型映射、工具入口、任务处理和统一错误。
- D:/项目/智能化/server/migrations：数据库演进。
- D:/项目/智能化/server/tests：单元、接口、授权、流程与恢复测试。
- D:/项目/智能化/tests/e2e：真实页面操作与视觉检查脚本和受控测试数据。
- D:/项目/智能化/data：本地开发的持久文件目录，不提交密钥与业务数据；正式路径由部署配置决定。

后端先按 identity、projects、documents、knowledge、assistant、system、jobs 七个领域目录或文件组织。单个文件足够时不建立接口工厂、插件市场和多层空抽象。浏览器或测试环境属于有外部边界的适配器，才需要明确协议。

## 四 数据约定与核心表

内部主键为不可预测 ID；显示名称与主键独立。UTC 保存时间，界面按明确时区显示。每个可编辑对象带 revision、created_at、updated_at 与操作者；不可变修订表用唯一的对象/修订号定位。所有项目对象保存 project_id，所有跨对象写入检查项目一致性，不能相信请求中的 owner 或 project_id。

大文件不放数据库正文中；file_id 指向受控目录，元数据包含哈希、类型、大小、拥有范围和存储状态。正文语义结构可用 JSONB，权限、状态、唯一约束、版本和检索关键字段用明确列。

|---|---|
| users | account 唯一、name、department、status、password_hash/外部身份引用、revision；原型用户不得直接被信任为已认证账号 |
| sessions | 随机会话令牌的服务端记录或哈希、user_id、失效时间、撤销时间、认证强度；不记录明文密码 |
| user_roles | user_id、能力角色；唯一组合；受限管理员不能为他人授予自身无权的高权限 |

| project_members | project_id + user_id 唯一、project_role、有效期；项目创建和初始负责人同事务 |

| evidence | run 或采集任务、step、file_id、角色、软件版本、用途、原图/派生图关系、审核与可见范围 |
| conversations / messages | owner_id、项目或库范围、模式、来源快照、消息顺序、消息类型、分享规则；敏感内容按范围再鉴权 |

### 4.1 约束、索引和事务

关键索引覆盖项目/状态/更新时间列表、用户待办、库与发布世代、文档块修订、任务可领取时间、事件顺序、被引用对象反查。查询在库内按权限与租户范围过滤，不先取所有结果再在浏览器隐藏。

事务边界：项目与初始成员；事实确认与影响事件；块修订与来源绑定；任务步骤完成与业务结果；审核决定与对应修订；正式基线与锁定清单。文件生成不能放长事务里，先写临时文件、校验、原子提交文件清单和数据库状态；孤儿临时文件按延迟清理。

删除默认软停用，并核对正式引用和保留政策。跨项目错误外键、同一资料新旧世代混用和无权限工具写入应通过数据库与服务层组合检查，不能仅在前端表单上限制。

### 4.2 候选与当前稿

Agent保存的候选修订、当前工作稿、已批准版必须独立识别；生成成功不自动切换当前稿。采用候选要校验当前修订及来源版本，人工已修改时返回冲突。可复用既有修订表与指针，不增加通用分支系统。详细采用行为及建议接口见 [开发契约补充](D:/项目/智能化/docs/完整开发方案/08-开发契约与遗漏补充.md)。

## 五 API 统一约定

前缀 /api/v1，JSON 使用统一字段命名；大文件单独流式传输。列表包含 items、page、pageSize、total、revision 或更新时间，page 从 1 开始；pageSize 有上限，sort 只能使用允许字段。total 必须是当前用户可见结果数量。

成功可返回 data 与 requestId；错误返回稳定 code、用户可理解 message、fieldErrors、requestId，可附版本冲突的当前修订。调试堆栈仅进入受控日志。典型状态：401 未认证，403 无权限，404 不存在或按防枚举策略隐藏，409 版本或状态冲突，422 字段或业务规则错误，429 超限，503 模型或执行环境不可用。

修改携带 expectedRevision 或 If-Match；二者选择一种统一实现。创建任务与正式导出支持 Idempotency-Key，并按操作者、范围、动作和请求摘要校验。同 key 不同请求返回冲突；同 key 同请求返回已有结果。

### 5.2 关键交互的请求响应示例

以下是接口合同示意，不是已经实现的 API。标识仅在请求数据中传递，UI 显示服务端提供的名称。操作者和权限从认证会话取得，客户端不能通过传 userId 替代身份。

单块生成请求 POST /blocks/{id}/generate，附 Idempotency-Key：

~~~json
{
  "expectedRevision": 3,
  "sourceVersionIds": ["source-version-example"],
  "continueReadySteps": true
}
~~~

服务端检查块属于当前可访问项目、模板已发布、来源可见和修订一致后返回：

~~~json
{
  "data": {
    "jobId": "job-example",
    "status": "queued",
    "target": { "documentName": "软件需求规格说明", "blockName": "登录功能" }
  },
  "requestId": "request-example"
}
~~~

客户端不能传 arbitraryPrompt 替代批准 Skill，也不能在这个接口扩大工具集。continueReadySteps 仅决定同一个目标任务内部就绪步骤是否继续，不隐含全项目授权。服务端根据模板规则决定哪些已确认来源可用；sourceVersionIds 是候选选择，不是绕过必需材料检查的开关。

知识检索 POST /knowledge/search 的请求字段为 query、projectId 或明确 baseIds、允许的版本范围、limit；两类范围的组合规则在服务端验证。返回每条 hit 的 sourceName、sourceVersion、headingPath、定位数据、excerpt 与内部引用 token；返回空数组必须代表真实无命中，解析服务不可用应返回错误。

版本冲突不写入当前修订，返回 HTTP 409：

~~~json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "此内容已被更新，请比较后再保存",
    "currentRevision": 4
  },
  "requestId": "request-example"
}
~~~

任务事件包含 jobId、sequence、type、stageName、targetName、status、可见结果引用。sequence 单调递增，客户端按最近序号续传并去重；UI 不展示内部 jobId。成功事件分别表示步骤完成、候选草稿可用或任务完成，不能用同一事件替代“审批通过”。

上传接口使用受限 multipart，返回资料版本标识和解析任务；文件字段、库授权、字节上限在开始读取前及读取过程中检查。大文件分片上传不是首版必须能力，超过批准大小要明确拒绝，不接受到磁盘爆满后才报错。

## 六 单 Agent 与持久任务

任务表采用已排队、执行中、等待输入、暂停请求、已暂停、取消请求、结果待核实、成功、失败、已取消状态；步骤有独立尝试与检查点。API枚举、错误码、批量部分失败和取消中行为按 [开发契约补充](D:/项目/智能化/docs/完整开发方案/08-开发契约与遗漏补充.md) 冻结，前后端不得各自定义。任务自身成功表示规定范围已处理，不自动表示全部测试通过或文档已审批。

领取任务用短事务行锁和租约，外部模型或浏览器调用期间不持有数据库事务。PostgreSQL 的 SKIP LOCKED 可用于避免多个领取者互相等待，但其返回视图不适合通用一致性查询，应用仍须处理租约、重试与结果提交。[T02]

每次领取递增执行世代或 fencing token，保存结果时验证当前世代与租约，防止超时旧 worker 回写。外部非幂等操作不能靠数据库 token 自动保证只执行一次；它还需要动作记录、测试唯一数据和未知结果核实流程。

Agent 由程序驱动有限循环：选就绪目标 → 构造上下文 → 模型提议 → 校验 → 必要工具 → 校验结果 → 保存候选 → 更新任务 → 下一轮。项目事实、已批准内容、来源索引与进度持久化；不依赖常驻模型会话永久记忆。工作记忆可以含带标签的当前任务草稿，正式下游事实必须读取已确认版本。

长时间模型生成、解析、测试和导出不放在单个 HTTP 请求或仅内存队列。FastAPI 的后台任务接口不是持久队列，官方亦提示重型后台计算需考虑独立工具；本方案用数据库任务和独立 worker，不据此默认引入 Redis/Celery。[T01]

事件序号用于断线续传；SSE 连接断开不取消任务。使用同源 cookie 鉴权并复查会话，权限撤销中止推送。高敏感事件仅发引用和摘要，日志正文按权限单独读取；禁止把完整来源或密钥广播到项目通道。

## 七 身份、权限与安全

### 7.1 认证方案

公司无既有 SSO 约束时，建议服务端会话加 HttpOnly cookie；生产环境强制 TLS、Secure、适当 SameSite、限定 Path 和寿命，并在登录/权限变化时轮换会话。会话过期、退出与停用要在服务端真正撤销。开发用 localhost 的 cookie 与代理策略需单独受控，不把开发 HTTP 配置用于生产。[T03][T04]

密码使用成熟库进行 Argon2id 等批准的慢哈希，不明文、不可逆加密、不自写密码算法；具体参数根据安全基线与硬件校准。SSO 接入后本地密码策略与外部身份映射重新评审。[T05]

基于 cookie 的写请求增加 CSRF token 和来源校验，不只依赖 SameSite；CORS 限制批准来源。使用同源 /api 代理减少不必要的跨域配置，不将通配 origins 与凭据混用。[T06]

设置登录失败限速、通用错误提示、会话绝对和空闲超时、敏感操作再认证与必要审计。前端路由守卫仅用于交互，真正权限始终在 API、检索、文件和执行工具边界验证。

### 7.2 工具及资料边界

工具请求仅使用注册动作和对象 ID，服务器自行解析路径；限定命令、网络目标、重定向、工作目录、资源和输出，禁止输入字符串拼接自由 shell。上传解析限制类型、大小、压缩展开量、超时和外部资源。富文本/Markdown 输出清理脚本和危险链接；SQL 使用参数化查询。

代码、网页、OCR 与知识材料都可能包含提示词注入；这些内容只能作为数据。工具网关不允许资料内指令扩张项目范围、调用外部网址或读取秘密。模型密钥和浏览器 cookie 由凭据引用注入执行环境，不进入普通提示词和日志。Playwright 官方明确提醒认证状态可包含足以冒用用户的敏感信息。[T08]

业务数据默认不出批准内网。管理员可配的模型或解析地址也需网络白名单与审核，不能用任意 URL 测试接口形成 SSRF。项目成员撤销后，检索缓存、助手消息、证据下载和任务继续执行都重新验证权限。

### 7.3 运维边界

审计是访问受限的追加记录，文件哈希用来检查完整性；没有签名与独立保全机制时不宣称不可篡改。备份涵盖数据库和相关文件的一致恢复点；恢复需抽查引用、文件哈希、会话失效和审批版本。保留期、恢复目标与审计授权待公司确认。

## 八 部署与非功能验收

开发前端入口固定为 http://localhost:5173，测试脚本不能静默切换 5174。正式服务地址、HTTPS 终止和内网证书另行确认；不能把 localhost 误当全公司共享访问地址。

API、worker、数据库和工具运行环境分身份部署。Linux 或 Windows 选择由公司测试语言和办公渲染环境决定；模板渲染不因服务器方便而降低 Word 验收标准。离线依赖包含批准版本的浏览器、语言工具链、字体、模型服务连接和解析器。

拟定性能目标需在固定样本下实测：登录、项目列表、知识检索、单块生成、上传可用时延、任务恢复、导出时长、并发队列与磁盘容量。不给未经实测的吞吐承诺；开发阶段先记录基线，再由负责人冻结可验收阈值。

监控重点是失败任务、失去心跳、存储接近上限、索引代际不一致、模型限流、导出失败与权限拒绝异常。一般健康检查不返回秘密，不能让模型不可用造成所有项目资料页面不可用。
