## 3 与系统设计直接相关的结构

- SRS 存在按软件能力、接口等重复展开的说明，需定义固定模板块及其重复实例。
- STD 包含测试准备、测试输入、预期结果、评价准则、步骤和假设约束，不能只保存一段“测试通过”的正文。
- STR 包含结果总结、遇到问题、与测试规程不一致等要求，说明报告需要保留真实失败、异常和偏离记录，而不只是成功截图。
- SUM 除处理规程外，还包含软件环境、安装设置、访问控制、数据备份、故障恢复和消息等，需多来源材料支撑。
- 模板指导文字应作为编写要求提取；示例编号应映射为重复区；固定正文和签批栏目须由负责人确认用途。
- 发现的疑似错字作为模板维护问题列入评审，不静默修订原件，更不能把模板自身问题归因于模型生成。

测试场景与正式文档映射尚待用户确认。建议先区分“函数级测试/功能测试”与“计划/说明/报告”，再决定分别建立哪些文档实例。
