本轮用户已授权检查、制定计划并继续开发。本文是当前任务入口；2026-10-09 的需求整理中“暂不开发”已被后续授权替代。历史交接中的 PostgreSQL、固定密码禁用、手机适配、复杂审批等说明不作为当前实施要求。

## 一、必须遵循的范围

- Vue 3、Python/FastAPI、SQLite；开发前端固定为 http://localhost:5173，按 1920×1080 截图验收。
- 当前本地固定账号为 `admin / admin123`，不在启动时自动改密码或要求该账号改密。
- 系统管理始终排在业务一级导航之后，包含用户管理、模板管理、Skill 管理；项目仍以概述和文档编写为主要入口。
- 支持多人编辑同一文档的不同段落，不要求实时输入同步；不增加审批链。
- Word 模板中的提示是 AI 编写指导；模板管理内全部内容最终都应可编辑。写作时保留原指导依据及本篇调整。
- 单份文档发布为“需求规格说明 v0.1 / v0.2”，不把多份文档组合成产品基线。
- 任务书、需求、设计要能按具体内容建立一对多关联；图表、图片、Visio 支持标题和自动编号。暂不增加 AI 图片生成。
- 用户授权的本地私有部署包需携带当前数据及 AI 配置，迁移后可继续使用；不把密钥提交到 Git。

## 二、判定口径

“已实现”表示代码路径存在；“已验证”必须有对应测试证据。不能用接口存在代替完整操作，也不能用 XML 检查代替 Word 实际渲染。没有截图的前端任务只记为待界面验收。

## 五、实施顺序与改动边界

1. **先修运行和结果可靠性**：A01、A02、A03、A04、A14。复用原有 API、格式处理、记忆和快照工具，不新增框架。开发记录在本文件更新。
2. **先打通多人入口，再完整模板与分工**：A05、A06、A07、A15。不能只提供成员后台接口就称支持团队编写。
3. **建立确定版本后做关联与多文档**：A08、A09、A10、A20。日常修订和发布版本分开，旧资源不漂移。
4. **对象和导出**：A11、A12、A13。先确认源资源和题注，再做经确认的目标规范转换。
5. **每轮联合验收**：A18 持续执行，A19 在实际输入齐备后执行。最终部署包应基于通过验收的代码重新构建，不能将旧 exe 当成新版。

本轮不改原始模板、不清空业务库、不覆盖既有文档、不把 API Key 提交到 Git、不推送新代码到 GitHub。业务数据库迁移或写入前保留可恢复备份。当前任务不需要更换 Vue、DeepAgents 或 SQLite。
