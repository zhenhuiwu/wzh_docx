# 项目文档智能编制系统需求规格与风险审查

版本：v0.1 评审稿  
日期：2026年9月24日  
状态：开发前设计，尚未实现，也不代表已完成标准符合性认证。

## 1 目标与结论

本系统服务于公司内部研发文档工作。以项目为单位管理一组相互关联的文档，使用公司本地大模型，由一个 Agent 通过多轮小任务编写、执行经授权的采集或测试、保留证据，再用经过批准的 Word 模板输出文档。系统的主要价值是减少重复录入、找材料、执行后整理证据、排版和交付核对的成本，而不是单纯提高生成字数。

推荐采用模块化单体应用、单 Agent 执行器、确定性任务调度和版本化项目资料。先完成一条真实交付链路，不先建设多 Agent 平台、通用低代码工作流或完整在线 Word 编辑器。

本文将内容分为三类：已确认需求来自本次对话；建议设计是便于实现的默认方案；待确认项必须在相关能力正式开发或验收前决定。建议不等于用户已经同意。

## 2 已确认需求

| 编号 | 需求 | 验收方向 |
|---|---|---|
| R01 | 管理多个项目，每个项目有一组实际文档 | 项目可创建、查找、切换、归档；项目资料互相隔离 |
| R02 | 使用公司本地大模型 | 模型连接与调用在授权网络内；业务材料不默认发送到公网服务 |
| R03 | 使用现有 438C-2021 模板体系 | 保存原件，在副本上提炼；不得因套用文件名就声称满足全部标准 |
| R04 | 每个模板绑定专属 Skill | 模板、字段规则、Skill、块级提示词和校验要求作为配套版本发布 |
| R05 | 不让 AI 一次生成整份或整套文档 | 一轮只提交一个明确目标块或子任务；服务端拒绝越界写入 |
| R06 | 同一个 Agent 多轮工作，共享项目记忆 | 可持续推进与中断恢复；项目间不共享业务会话或未授权资料 |
| R07 | 重要内容块使用专属提示词 | 提示词绑定具体输入、输出字段、来源和禁止事项；普通用户无需维护提示词 |
| R08 | 项目文档相互引用并保持一致 | 公共事实唯一来源；引用绑定对象与版本；变更能定位受影响内容 |
| R09 | Word 字体、标题、间距等严格受控 | 由模板和程序控制；结构检查与最终页面检查分别验收 |
| R10 | 单元测试以函数为主要单位 | 对选定函数准备、执行测试并保存可追溯结果，不凭模型口述判定 |
| R11 | AI 操作前端进行功能测试与截图 | 用例先定义预期；操作、断言、实际结果、证据可对应 |
| R12 | AI 操作前端采集用户手册截图 | 按用户任务采集真实页面，生成对应说明；不伪造界面 |
| R13 | 软件易用，尽量减少重复操作 | 用户面向项目待办、内容块和证据，不必反复粘贴材料或手动发送“继续” |

## 3 本地模板盘点及其影响

检查目录：D:/项目/智能化/438C-2021全套模板。

目录中实际发现 20 份 DOCX，名称包含 SDP、SIP、STrP、STP、OCD、SSS、IRS、SSDD、IDD、SRS、SDD、DBDD、STD、STR、SPS、SVD、SUM、CPM、FSM、SDSR。已只读提取 OOXML 结构、文件哈希、标题样式段落、表格、分节、域等信息，未修改模板。

检查范围仅为文件清单、XML 结构和选定章节的文本，不包含全部页面渲染、对标准正文逐条核查、正式文档验收或排版认证。

关键发现：

1. 未发现现有 Word 内容控件。不能直接把这批文件视为已经完成机器化标记的模板；现有文字或示例是否可作为占位符，需要逐项核对。
2. 有多节文档、表格、目录域及不同标题样式。提炼不能只做全文字符串替换，也不能仅靠标题样式推断所有正文结构。
3. SRS 含“3.2.X（软件能力）”等结构；STD 含“4.X.Y（测试用例……）”；SUM 含“5.3.X（软件使用方面）”。这些应映射为受规则约束的重复内容块，而非让 AI 自由增加章节。
4. 文件清单中没有单独命名的“单元测试”或“功能测试”模板。目前可见 STP 软件测试计划、STD 软件测试说明、STR 软件测试报告。测试类型与文档类型是两个维度，需确认是否分别实例化 STD/STR，或另有公司专用模板。
5. SUM 不只有操作截图，还含软件环境、安装和设置、访问控制、备份、故障恢复、消息等内容。这些要从已确认运维或产品资料取得，不能通过点击页面推断。
6. 模板含编写指导文字及疑似文字识别或录入问题。例如 STR 中出现“文裆概述”等文本。将其列为模板复核项，不擅自更改原件或宣称模板整体不合格。

详细机器盘点见同目录附件。模板中的标题名称属于用户提供文件内容，不据此判断标准规定必然如此。

## 4 业务对象与范围

项目是资料隔离和权限边界；模板集是可选模板版本的组合；文档实例是项目真正维护和交付的文档；同一模板允许因测试类型、子系统或交付阶段产生多个文档实例。各文档实例具有独立编号、用途、版本和状态。

内容块是最小受控编写单位，可为一个说明段落区、表格、图片区、需求条目、函数测试记录或用户操作规程。重复块的实例具有稳定 ID，章节号由程序计算；不能把显示序号当唯一标识。

资料是原始输入；项目事实是经过确认的结构化信息；证据是某次实际执行产生的记录；草稿不是事实。手册操作完成也不自动等同于功能测试通过。

正式交付按一组明确文档和证据版本建立快照。没有要求所有文件都用相同版号，但引用必须能对应这次交付。

### 4.1 第一阶段建议范围

- 内网多人可访问的 Web 管理界面，角色先只设系统管理员、项目负责人、编写或测试人员、审核人员。
- 先支持公司最常用的一种代码语言和测试框架；明确版本后再实现适配。
- 功能测试与手册采集先以一种受支持浏览器中的 Web 应用为对象；桌面原生软件、复杂画布等暂不承诺。
- 全套模板可以登记；正式发布为“可生成”之前，逐个经过字段映射、样例填充和验收。
- 首批建议覆盖 SRS、SDD、STD、STR、SUM 所代表的实际交付需求；优先顺序由最耗时场景确定。
- 支持手工上传已有测试结果和截图，避免工具适配尚未完成就堵塞整个流程。

### 4.2 明确不作为首版目标

不以完全无人审核、任意语言自动生成测试、任意页面自由探索、自动修复所有业务代码、全面往返同步外部 Word、通用项目工时管理、多 Agent 自组织、自动认定标准合规为目标。没有实测规模压力前，不引入独立图数据库、向量库、微服务集群或额外消息中间件。

## 5 应补充的功能要求

| 编号 | 建议补充要求 | 原因及验收方法 |
|---|---|---|
| R14 | 模板适用性裁剪 | 不是每个项目必须交付全部 20 份；不适用项需理由和审批，不能静默删章 |
| R15 | 已确认事实与草稿分层 | AI 提出的新事实先为候选，确认后才能供下游作为权威依据 |
| R16 | 人工修改保护 | 重新生成形成新草稿和差异，不覆盖人工批准版本；并发修改产生冲突提示 |
| R17 | 执行记录与文档描述分离 | 重写说明不重跑测试；重测新建记录，不擦掉失败历史 |
| R18 | 失败与中断恢复 | 保存任务检查点；未知副作用不能盲目重试；暂停有明确状态 |
| R19 | 项目级权限和审计 | 检索、下载、预览、工具调用均校验项目权限；关键更改留操作记录 |
| R20 | 受控运行环境 | 指定代码副本、测试环境、账户、网络和工具权限，不默认操作生产环境 |
| R21 | 图片和材料版本 | 图片保存来源、时间、角色、软件版本；支持有记录的裁剪、标注和脱敏 |
| R22 | 格式回归与交付检查 | 原模板保护、缺字段检查、长表格或多图渲染验证、审核记录与交付清单 |
| R23 | 调用预算和运行可观测性 | 显示真实阶段、步数、耗时、错误；限制轮次、重试和工具执行时长 |
| R24 | 备份与保留策略 | 数据库、素材和交付包一致备份，恢复演练；审批后的保留期限与删除规则 |
| R25 | 模型和规则变更回归 | 模型、模板、Skill、提示词升级可追踪；旧交付仍引用原版本 |

## 6 不合理或容易误解的地方

| 问题 | 修正建议 |
|---|---|
| 只要 Skill 写得严格，模型就不会发挥 | Skill 是指导，不是安全和正确性边界。字段白名单、来源校验、写入范围和工具权限由程序执行 |
| 同一个 Agent 就会永久准确记住所有材料 | 把记忆持久化并分级，按任务选择上下文；长对话摘要不能替代原始证据 |
| 所有块都让 AI 写 | 项目名、数值、编号、执行结论等直接从权威数据填入，只让模型承担有必要的语言组织 |
| 模板填好就必然格式完全一致 | 先确定目标 Word 或 WPS 版本、字体和渲染方式；页数变化允许，规则与版面质量需验证 |
| 自动生成测试，再自动通过，就说明代码正确 | 预期依据不能只来自被测实现；缺少需求或设计约定时先人工确认；覆盖率不作为唯一质量结论 |
| 最初提到的“并发”都归单元测试 | 本方案将函数并发行为检查与系统并发或性能测试分开；压力测试目标、环境和工具另行确认 |
| 功能测试只需截图 | 用例要有判定条件；截图是证据之一，没有可信判定时标记待确认 |
| 用户手册只是成功路径截图 | 截图覆盖操作规程，安装、恢复、安全或备份等还要对应资料和适用性判定 |
| 单 Agent 必须拥有所有权限 | 使用同一执行器但按当前任务下发最小工具权限；编写任务无权运行测试或删除数据 |
| 自动重试可以解决所有失败 | 读取和生成可有限重试；提交、删除等副作用操作在结果未知时必须先核实 |
| 测试失败就不能生成正式报告 | 可以正式报告失败；禁止的是伪造结果、缺失必需证据或未处理的引用错误 |
| 自动检查过就可以代表公司审批 | 系统记录技术检查与人工签审两个维度，不伪造签名，不替代指定责任人 |

## 7 尚未解决的决策

| 编号 | 需要确定的事项 | 当前建议或默认 | 影响 |
|---|---|---|---|
| D01 | 本地模型接口、模型版本、上下文限制、工具调用和结构化输出能力 | 用真实样例做能力试验，不假设兼容任何指定 API | Agent 调用与失败处理 |
| D02 | 被测代码主要语言、框架、构建方式及依赖来源 | 首版仅适配一个真实代码环境 | 单元测试执行器 |
| D03 | 前端是否主要为 Web；浏览器、SSO、验证码、上传下载及弹窗要求 | 先定义一个受支持的 Web 环境，登录难点允许人工接管 | 浏览器执行器 |
| D04 | Word 验收软件、版本、字体、页面样例及标准裁剪规则 | 以公司认可的模板副本和合格样例为准 | 排版和渲染方案，开发前关键决策 |
| D05 | 单元和功能测试各自要哪些正式文档 | 测试场景与 STD/STR 文档实例分开建模 | 模板清单与关系 |
| D06 | 用户量、并发量、审核责任和是否要求编审分离 | 首版角色授权，生成队列默认串行；容量目标实测后冻结 | 部署、调度和权限 |
| D07 | 测试环境、账号、数据恢复及允许的业务操作 | 专用非生产环境、演示数据和操作白名单 | 安全与可重复执行 |
| D08 | 离线或保密边界、网络出口、日志与证据保留期限 | 业务数据默认不出授权内网；外部依赖需批准 | 包分发、审计、存储和备份 |
| D09 | 导出的 Word 是否允许外部修改并再次纳入系统 | 首版作为修订附件导入并人工按块合并，不承诺全自动往返 | 编辑器和版本管理 |
| D10 | 设计图、公式、复杂表格及 PDF 是否属于首版正式输出 | 先支持已确认图片或附件引用；复杂新生成能力独立验收 | 模板及素材类型 |

D01 到 D05 是首轮原型必须明确的输入，D07 和 D08 是任何实际执行之前的前置条件。其余事项可以采用书面默认值推进，但正式上线前需要负责人确认。

## 8 质量与非功能要求

安全和一致性是门槛，不是可推迟的装饰功能。所有资料读取和对象写入同时受用户、项目和任务范围约束；密钥不进入提示词、普通日志或导出件；代码、网页和上传文档均作为不可信数据处理。

应用页面切换、查询响应、单块生成时间、浏览器任务时长、并发用户数等具体指标，须在指定内网环境与模型硬件上测量后写入验收表，当前不编造吞吐量。任务在模型不可用时可被明确标记和恢复，不得无限等待。

可靠性至少覆盖服务重启后的队列恢复、人工修改冲突检测、素材损坏或丢失提示、备份恢复演练，以及非幂等操作中断后的人工核实流程。所有导出使用确定版本输入；模型内容不保证每次生成字节相同，已确认内容固定后可重复导出相同业务版本。

## 9 开工结论

需求方向合理，已经可以进入受控验证阶段，但不宜直接按“本地模型加 Word 导出”开始堆页面。必须优先证明四件事：真实模板能稳定输出合格页面；本地模型能在受限字段内完成多轮任务；受控环境能取得可信测试和截图记录；上游变更能正确影响下游而不破坏已批准版本。

具体架构、界面、状态转换和验收清单分别见本目录其他说明。所有实现仍须对上述待确认项进行决策，本文未批准生产操作、公开部署或第三方数据上传。
