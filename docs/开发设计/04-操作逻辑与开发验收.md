# 项目文档智能编制系统操作逻辑与开发验收说明

版本：v0.1 评审稿  
日期：2026年9月24日  
说明：以下是拟实现流程和验收条件，不表示软件已经实现或测试通过。

## 1 状态模型

### 1.1 文档内容状态与有效性分离

内容修订状态为草稿、待审核、已批准、已退回。已批准修订不可直接原地编辑，修改时创建新草稿；以前的修订仍可追溯。

有效性单独记录为当前有效、上游已变化、存在冲突。一个块可以同时为“已批准”和“上游已变化”，此时批准历史保留，但不能把它静默纳入新的正式基线。

“不适用”是经确认的适用性决定，不是生成失败。应记录理由、范围、审批和模板中的表达方式。

文档状态从块和审核要求汇总：准备中、编写中、待审核、可交付、已发布。是否存在缺材料、失效引用和冲突采用独立问题列表，不把所有组合堆成一个难以维护的枚举。文档状态不代表被测软件质量结论。

### 1.2 任务状态

~~~text
已排队 → 执行中 → 成功
             ├→ 等待输入 → 补充后重新排队
             ├→ 请求暂停 → 已暂停 → 恢复后重新排队
             ├→ 结果待核实 → 人工或工具核实 → 继续或终止
             ├→ 失败
             └→ 已取消
~~~

恢复必须重新检查授权、输入版本、租约和外部环境，而不是直接重放上次动作。取消后保留已生成草稿和执行证据；是否清理测试数据按已批准清理步骤处理。失败任务再次尝试保留原尝试记录。

### 1.3 测试结果

运行完成状态与业务断言结果分开。运行可能完成、工具错误、中断或结果未知；单用例判定为通过、失败、阻塞、跳过或待人工确认。没有运行或没有可信判定不能标为通过。

统计明确分母以及跳过、阻塞和重试的处理，默认保留每次尝试，不用最后一次通过抹去前次失败。正式测试报告可以包含失败、未执行和限制，但必须如实说明，并满足项目约定的证据和审批要求。

## 2 F01 创建项目及文档集

入口：P01 新建项目。

前置：用户有创建权限，至少一个模板集可登记。

操作：填写项目标识、名称和软件范围；选择模板集及版本；按适用性选择文档；设置负责人；创建文档实例和初始缺口清单。可为同一 STD 或 STR 模板创建单元、功能等多个用途明确的实例，编号分别维护。

项目可以在资料不全时创建，但不允许把未适配模板默认为可生成。复制项目时展示复制清单，默认不复制证据、执行结论、凭据和旧权限。模板原件的复制不等于原项目资料授权。

结果：项目和文档清单建立，首页出现可操作待办，不自动开始测试或模型调用。

## 3 F02 提炼并发布模板包

入口：P08 模板与规则，仅模板管理员。

操作顺序：

1. 上传或登记原件，计算哈希，记录来源和使用范围。
2. 提取标题、表格、域、样式和指导文字；形成候选映射。
3. 人工确认固定文字、直填字段、AI 正文、图片、重复区及条件适用项。
4. 为文档绑定 Skill，为需要 AI 的块绑定专属提示词，定义 schema、依赖和验收规则。
5. 用固定测试数据试填，至少覆盖空可选项、缺必填项、长段落、长表格、重复嵌套、多图、特殊字符和编号变化。
6. 检查最终 DOCX 打开、字段更新和页面质量；在指定办公环境由负责人确认。
7. 发布不可变模板包版本，记录验证样例和已知限制。

失败处理：标签结构错误、样式丢失、目录未更新或页面问题不能通过“提示词再严格一点”绕过，回到模板与渲染层修复。发布后修改创建新版本；已有项目是否升级要单独确认。

## 4 F03 导入资料并确认项目事实

入口：P04 上传资料或填写事实。

原件保存后异步解析；解析失败保留原件和错误，允许人工登记。模型可辅助抽取候选事实和来源定位，但不能自动把冲突值标为确认。

用户确认事实时查看来源、适用版本和当前值。事实变更写入新修订并触发影响分析；历史文件和已交付文档不跟着变化。缺少来源但确属人工决定的内容，应明确标为“人工确认”，记录责任人与时间，而不是伪造材料引用。

照片、截图和测试结果分别标记类型；手工上传的图片可以作为素材，但必须注明人工来源，不能标记为 Agent 自动执行证据。

## 5 F04 开始文档任务及逐块编写

入口：P03 编写本块或开始文档任务。

前置：模板包已发布；目标块定义存在；用户有权限；必需资料和前置依赖满足。文档批量任务允许部分块就绪、部分块等待，但最终状态必须如实显示未完成项。

~~~text
用户选择范围并确认
  → 保存任务及输入快照
  → 确定性字段直接填入，AI 任务进入队列
  → 装载本项目记忆、文档 Skill、当前块提示词
  → 执行本轮小任务
  → 校验结构、事实、引用、范围和版本
  → 保存新草稿及来源
  → 更新进度；有预算且下一块就绪则继续
  → 需要人工时停在明确的待办
~~~

块生成前和结果提交时都检查输入版本。若生成期间用户已修改同一块或上游已变更，候选结果不能直接替换当前版本；显示差异和失效原因。

缺材料时给出具体清单与填写入口，不用泛泛文字填满必填章节。结构错误允许有限修正；修正仍失败就保留诊断并停止。本地模型调用预算、最大工具步数和修正次数都应可设为有限值。

人工编辑不要求模型再次审核才允许保存；提交审核和正式导出时仍执行必要检查。批准某块不等于批准整份文档；审核驳回只要求修改相关块。

整份检查只提出可定位问题。需要修订时创建对应块任务，禁止最后一次“全文润色”绕过前面的限制。

## 6 F05 函数级单元测试

入口：P05 单元测试。

前置：授权代码范围、固定代码版本、可用运行器、依赖来源、运行预算、测试输出目录和隔离环境已确认。

步骤：

1. 选择函数或已有用例，读取必要上下文。
2. 根据已确认需求或接口约定提出测试目标、输入、预期和依据；无依据的预期进入待确认。
3. 在测试副本中创建或修改测试文件，展示差异。禁止未经批准修改产品代码、扩大代码范围或自行调整断言迎合实现。
4. 在受控环境运行并记录命令摘要、代码哈希、依赖或镜像标识、用例版本和日志。
5. 解析真实结果；无法编译、环境缺失、测试本身错误、断言失败分别归因。
6. 保存 TestRun 与证据，按模板块生成测试说明或报告描述。

异常：不支持的代码语言、硬件依赖或隔离条件不满足，标记阻塞并允许导入人工测试结果。测试产生的错误日志可以辅助定位问题，但“修复业务代码”是独立授权任务，不是本流程默认步骤。

重写报告只重写文字；重新运行创建新的 Run。代码变更后旧记录保留，并对新交付标记是否需要重测。并发或性能测试是否纳入另行确认，不把压力测试自动塞进所有函数测试。

## 7 F06 功能测试与截图

入口：P05 功能测试。

前置：批准的目标环境与域名、测试账号、测试数据、用例版本、预期结果及清理方案。当前 Agent 具有此任务允许的浏览器工具权限。

步骤：登录或由人工完成登录；验证当前环境和角色；准备测试数据；逐步观察、操作、检查；按规则保存关键页面和失败现场；执行适当清理；保存运行记录与判定；生成相关文档块。

每轮只处理一个有边界的动作或检查，可以是打开页面、填写一个逻辑表单或验证一组明确字段，不强制每个键盘字符都单独调用模型。关键页面状态变化后重新观察，不能无条件发完长串鼠标动作。

判定规则来自用例：可验证的文本、值、记录状态等用确定性断言；只可人工判断的视觉或业务结果进入待确认。系统提示成功但业务状态未满足时，不直接通过。

非幂等异常处理示例：点击“保存”后超时，系统不知道服务器是否成功。先进入结果待核实，通过任务唯一测试数据查找结果或请求人工核实；只有确认未成功且允许重试才重新提交。无法核实就保留未知，不给出虚假的失败或成功。

页面结构不支持、定位不唯一、验证码或权限不足时暂停并说明原因。人工接管前停止 Agent 操作；归还后重新观察。禁止为绕过障碍私自读取生产数据或扩大浏览器权限。

清理失败记录为单独问题并提醒负责人，不删除无关数据，也不把清理失败自动篡改成前面业务断言失败。

## 8 F07 用户手册截图与说明

入口：P05 手册采集，或 P03 SUM 某个操作规程的“采集素材”。

前置：确认功能范围、适用角色、演示数据、软件版本及任务流程。操作权限与功能测试相同受控，不因叫“采集”而忽略副作用。

步骤：确定一个用户任务；读取当前规程材料；检查可复用素材；实际操作并保存关键步骤图；整理步骤记录；生成本块说明；逐项核对菜单、按钮、输入、结果和图题；人工确认后纳入文档。

图像处理只允许有记录的裁剪、遮挡、箭头和序号等，不生成伪造产品界面。操作中失败时记录异常；不能用图像编辑将失败改成成功路径。

对于 SUM 的安装配置、备份、恢复等内容，使用已确认资料或授权验证流程。未做灾难恢复演练就不得写成“已验证可以恢复”，应区分操作规程说明与实测结论。

截图复用需要校验软件版本、角色、界面状态、数据适用性和内容可读性。手册的操作记录可关联原测试记录，但不能反向证明测试覆盖。

## 9 F08 项目变更与一致性处理

入口：修改已确认事实、需求、设计资料、代码构建或软件版本。

处理：保存新版本 → 沿显式关系寻找直接和间接影响 → 去重形成变更清单 → 按规则标记文字复核、重测、重截图或引用更新 → 用户逐项确认 → 必要时生成新块或新 Run → 再审核。

例如，输入长度上限由 20 改为 40：设计约束要复核，边界用例和实际执行可能要更新，手册中的长度说明可能要修订。旧报告中真实使用 20 的执行数据不能替换成 40，旧软件交付仍保持原事实。

自动影响分析只覆盖已登记关系；对没有显式结构的长篇文本可以辅助搜索和提示，不能宣称绝无漏项。决定某项无需变动要记录理由，不能简单删除告警。

语义引用循环不等于任务调度循环；生成任务若形成循环依赖，展示原因并由负责人调整确认顺序，不让 Agent 无限相互改写。

## 10 F09 审核、导出和发布

入口：P07 审核与交付。

1. 选定文档实例、软件版本和交付范围。
2. 按文档类型执行内容与来源门禁。STD 可描述计划用例，不要求所有用例已运行；STR 必须如实给出实际执行或未执行情况，并满足本项目批准的报告要求。
3. 检查必填项、事实一致性、引用对象、适用性、签审、证据完整性及版本。
4. 从确定的数据快照生成 DOCX，解析确认无残留机器标签、非法关系或缺图。
5. 按已确认方案更新域、生成预览，检查长表格、多图、编号、目录、页眉页脚和分页。预览不等于目标办公环境验证，适用时保留人工检查关口。
6. 审核人员核对并批准交付。
7. 建立不可变基线，保存文档、数据清单、规则与模型版本、相关证据标识及文件哈希，提供下载。

如果导出中途有新的项目更改，不把新内容混入当前快照；提示使用旧快照或重新开始。正式导出缺失强制资料、未解决冲突或存在无效引用时阻止发布，并定位修复入口。

测试失败本身不默认阻止真实报告导出。软件上线批准若要求全部通过，应另建公司发布门禁，不在文档生成层偷偷修改结论。

## 11 F10 规则升级与外部修订

模板、Skill、提示词或模型配置变更，创建新版本并运行固定回归样例。项目可选择升级，系统先展示字段变化、缺失映射和影响块；不原地更换已发布文档的依赖。

外部修改 Word 的首版处理：上传为修订附件，记录来源版本，按块人工核对合并，形成新草稿。外部文件中的截图、标题变化或删章不自动成为系统事实。完整自动双向编辑同步暂不承诺。

## 12 开发前验证与分期

### G0 关键假设验证

- 取得本地模型调用样例和能力上限，验证块级结构输出、工具请求、缺材料停机及重启后的状态恢复方式。
- 选 SRS 的正文与重复需求、STD 或 STR 的重复测试结构、SUM 的多图操作规程等代表性区域，使用真实模板试填并在指定办公环境验收。
- 选择一种真实代码环境中的少量代表函数，覆盖可通过、应失败、无法运行等情况，验证真实结果链路。
- 选择一个授权 Web 功能和手册任务，验证登录、控件定位、断言、截图、暂停和提交结果未知的处理。
- 确定模板与测试文档映射、目标办公软件、执行环境和数据安全边界。

G0 必须有记录的结论，不能用一份看起来漂亮的生成文件替代。任一关键假设不成立时缩小支持范围或采用人工接入，不能掩盖限制。

### G1 基础闭环

项目与模板版本、公共事实、资料、内容块、单 Agent 多轮任务、草稿与审核、Word 填充、手工证据导入、交付快照。优先把一份真实文档从资料到交付走通，同时建立权限和审计基础。

### G2 特殊场景

先接入最急需且已通过 G0 的自动化场景，再接入另一场景。单元测试和浏览器自动化按适配环境分别上线，功能测试与手册共用受控浏览器能力。新环境未验收前继续使用人工导入，不强求全部同步上线。

### G3 一致性与交付强化

跨文档关系、变更影响、回归样例、模板批量适配、目标办公环境检查、离线分发、备份恢复和权限复核。G1 已有版本绑定与来源保存，G3 是增强影响自动化，不是到最后才补数据一致性。

### G4 运行优化

根据实测瓶颈优化调用次数、检索、排队和素材复用。没有证据前不增加多 Agent、微服务、向量库或全面可视化流程设计器。20 份模板按公司实际交付优先级逐一验收，不用首版一次适配完来阻塞闭环。

阶段时间和人力须在 G0 后按已选语言、模型能力和模板复杂度估算，当前不提供无依据工期。

## 14 效果度量

在真实文档上比较人工基线和系统辅助后的总耗时，分别记录资料准备、模型等待、测试执行、人工修订、排版修正和审核时间，不能只统计 AI 生成速度。

同时记录首次审核通过的块比例、事实或引用错误数、手工修订量、旧版本证据误用次数、重跑次数、模板格式返工量，以及人员对任务定位和资料补充的完成率。样本规模、目标阈值和统计周期由试点后确定，不把模型多轮调用自动等同于更快或更便宜。

开发开始前至少确认 D01 至 D05 和执行所需 D07、D08。具体问题清单见 [需求规格与风险审查](D:/项目/智能化/docs/开发设计/01-需求规格与风险审查.md)。
