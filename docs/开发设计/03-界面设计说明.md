# 项目文档智能编制系统界面设计说明

版本：v0.1 评审稿  
日期：2026年9月24日  
交付范围：信息架构、页面布局、操作入口、状态和交互规则；本次不实现前端，也不宣称已经完成可用性测试。

## 1 产品定位与视觉方向

面向公司内部编写人员、测试人员、项目负责人和审核人员，采用桌面优先的内网工作台。核心任务是检查项目缺口、编写内容块、核对证据并完成交付。首页不是聊天机器人，不采用大面积装饰图和通用 SaaS 卡片墙。

设计主题为“文档案卷与证据并排核对”：正文是工作中心，目录定位上下文，右侧证据栏回答“这句话依据什么”。项目状态通过紧凑清单、表格和可定位的待办呈现。只有需要比较或复核时才展开额外面板。

### 1.1 设计令牌

| 类型 | 建议值与用途 |
|---|---|
| 主背景 | #F4F6F8，承载工作区边界 |
| 文档与面板底色 | #FFFFFF，正文和证据承载面 |
| 正文 | #182534，标题和主要信息 |
| 次级文字 | #536477，说明、版本和时间 |
| 主操作与焦点 | #2454A6，用于开始任务、提交审核和选中项 |
| 边界 | #D7DEE7，用于表格分隔和面板边界 |
| 成功、警告、错误 | #267149、#9D6400、#B42318；必须同时显示文字或图标 |
| 字体 | 优先使用公司批准的本地中文 UI 字体，例如 Microsoft YaHei UI；其他系统使用已安装的等效中文字体，不从公网下载 |
| 字号 | 主页面标题 22px，区块标题 16px，正文和控件 14px，辅助信息 12px；允许用户浏览器缩放 |
| 间距 | 4/8/12/16/24/32px，表格与编辑区按任务密度分别使用 |
| 圆角与阴影 | 控件 4px，浮层 8px；普通文档面板不叠加装饰阴影 |

这里的 UI 字体与导出 Word 字体独立。网页缩略图不是正式排版验收结果。

无障碍目标包括键盘可操作、可见焦点、非颜色唯一提示、可读错误信息。普通文字按至少 4.5:1 对比度校核，大字至少 3:1；依据 W3C 对比度说明。具体组件还需在实现阶段测试，不因列出色值就视为整体达标。[T11]

设计复核后的取舍：取消默认大统计卡片、装饰渐变和大标题首页，把最重要位置让给“下一步待办”和“正文—证据对照”。仅保留有助于理解状态变化的轻量交互，不让长任务列表反复跳动；尊重减少动态效果设置。

## 2 信息架构与导航

全局入口：项目列表、模板与规则库、系统设置。普通用户不展示管理员专用入口。

进入项目后的导航：

~~~text
项目概览
文档工作台
项目资料
  已确认事实与术语
  原始资料与附件
测试与采集
  单元测试
  功能测试
  手册采集
关系与变更
审核与交付
~~~

“Agent 记忆”不作为普通用户的独立技术页面，而以“已确认资料”“历史决定”“任务进度”体现。管理员可查看模板 Skill 和提示词版本，普通用户只看到易理解的编写要求。

主要页面编号：P01 项目列表；P02 项目概览；P03 文档工作台；P04 项目资料；P05 测试与采集；P06 关系与变更；P07 审核与交付；P08 模板与规则；P09 系统设置。页面展示以下均使用示意数据，不表示已存在这些项目或执行结果。

## 3 P01 项目列表

默认表格而非同形卡片：项目名、软件或交付版本、负责人、待处理事项、已审核文档数、最近更新、状态。搜索项目名或标识，可按负责人、状态筛选。

创建项目向导分为：基本信息 → 选择并裁剪模板集 → 负责人及可用环境。只要求真正必须的字段，其余资料允许后续补齐。界面解释复制项目会复制什么：可以复制模板选择和经确认的配置，不默认复制旧测试结论、截图、成员权限和登录凭据。

归档项目保留交付与审计并限制新增任务；删除是不同操作，需要权限、影响提示和保留策略检查。首次空状态显示“创建项目”及所需资料说明，不显示虚构统计。

## 4 P02 项目概览

一屏回答四个问题：当前交付什么、有什么阻塞、哪些内容需要复核、下一步可以做什么。

~~~text
┌ 项目 A / 软件 V2.0 / 当前工作版本         [切换项目] [查看交付] ┐
│ 待办：3 项资料待补充   2 项变更待复核   1 项等待审核             │
├──────────────────────────────────────────────────────────────┤
│ 文档                    当前状态          主要问题        操作 │
│ 软件需求规格说明        待审核            2 块待确认      审核 │
│ 软件设计说明            需要复核          需求已更新      查看 │
│ 功能测试报告            材料不足          3 用例未执行    处理 │
│ 软件用户手册            编写中            2 任务缺截图    采集 │
├──────────────────────────────────────────────────────────────┤
│ 当前任务：手册 / 新增用户 / 观察提交结果                       │
│ 已完成 3 个步骤；等待结果检查              [详情] [请求暂停]  │
└──────────────────────────────────────────────────────────────┘
~~~

点击问题必须定位到对应块、用例或资料缺口。不要只跳到长文档顶部。

文档“可交付”与软件“测试通过”不是同一个状态：一份如实记录失败且审批完整的报告可以具备导出条件；软件发布是否允许则由公司另行规则决定。项目首页不能用单一绿色进度误导用户。

## 5 P03 文档工作台

采用目录、正文、依据三个区。进入编辑工作台后全局导航可折叠，避免 1366px 宽度下四个窄栏同时挤压。

~~~text
┌ SRS 软件需求规格说明 / 草稿 v0.3        [开始文档任务] [检查] ┐
├ 目录 220px ─────┬ 内容编辑区 自适应 ────────┬ 依据栏 320px ──┤
│ 1 范围          │ 3.2.1 登录功能             │ 本块要求        │
│ 2 引用文档      │ 状态：待审核 / 输入未变化  │ 所需资料齐全    │
│ 3 需求          │                            │                 │
│   登录功能 ●    │ 前置条件、功能描述等正文   │ 依据材料        │
│   权限管理 !    │ 或模板规定的结构化字段     │ 需求记录 v2     │
│ 4 合格性规定    │                            │ 接口资料 v1     │
│                 │ [编写本块] [保存草稿]      │                 │
│                 │ [提交审核] [查看差异]      │ 引用与问题      │
│                 │                            │ 1 条术语待确认  │
├─────────────────┴────────────────────────────┴─────────────────┤
│ 最近任务：本块生成完成；来源已记录。 [查看步骤和工具结果]       │
└────────────────────────────────────────────────────────────────┘
~~~

### 5.1 编辑与权限

- 固定标题、项目公共字段、计算编号只读，显示锁定原因及正确修改入口。
- 正文块使用受控编辑器；表格、用例和图片块用适合的字段编辑，而不是把所有内容塞进一个自由富文本框。
- 图片可查看来源、替换为已审核素材、添加允许的图题，不直接编辑图号。
- 已批准内容仍可发起修订，但产生新草稿，原批准版保留。采用修订号防止覆盖其他人的修改。
- 未保存更改离开页面时提示；自动保存状态必须区分“保存中”“已保存”“保存失败”，不能无提示丢失。

### 5.2 生成入口

“编写本块”只影响当前块。对已人工编辑的内容先展示将创建新草稿的说明，生成后提供差异，不自动替换。

“开始文档任务”打开一次任务确认：选取允许生成的块、展示预计依赖和缺口、确认是否自动继续处理就绪块。启动后后台分多轮执行，不能将这个按钮实现成一条整篇生成提示词。默认不包含重新执行测试或重新采集截图。

“使用建议”仅接受当前选定差异；修改涉及公共事实时，转到事实修改流程，不能在正文里悄悄改权威数值。

### 5.3 右侧依据栏

标签页为“要求”“来源”“问题”“历史”。来源显示对象名称、版本和定位信息，可打开原始附件或对应截图。要求显示面向用户的编写说明，提示词源码仅管理员可看。

每条问题有类型、位置、影响和处理入口。例如“截图采集自 V1.9，当前目标是 V2.0”旁提供“查看原图”“重新采集”“申请确认适用”，后者不等于直接豁免所有证据要求。

### 5.4 编辑与预览分开

编辑模式保障结构化输入，预览模式显示本次生成的页面结果。预览明确标明生成时间、内容版本、渲染环境及是否过期；不把网页编辑排版称为 Word 所见即所得。长文档按目录和页面定位，不为每次按键重新渲染整份 Word。

## 6 P04 项目资料

分为“已确认事实”和“原始材料”。事实字段显示值、来源、适用软件或版本、确认人和时间；用户修改后先进入候选或待确认，不立即改动已发布交付。

上传材料后显示解析状态、归属、建议关联、敏感级别和重复文件提示。系统提取出来的内容叫“候选信息”，不直接叫“已确认信息”。扫描件或解析失败文件可保留原件并手工补充，不隐藏失败。

术语和编号维护在此完成。跨文档重复事实只在这里修改一次；实际文档中显示受影响范围。材料权限对预览、搜索结果和下载一致，不在搜索摘要泄露未授权内容。

## 7 P05 测试与采集

### 7.1 单元测试页

左侧为代码范围、函数或测试用例列表；中间为当前用例的依据、输入、预期和测试代码差异；右侧或底部为执行结果和日志。

顶部持续展示代码提交或快照、语言运行环境和任务状态。操作为“分析选定函数”“确认用例”“运行选定用例”“查看记录”“编写对应文档”。运行前可见实际范围；不将代码扫描自动扩大为全仓测试或业务代码修改。

结果区分别统计通过、失败、阻塞、跳过、待确认。重试显示各次记录，不能只留下最后一次绿色结果。构建失败、测试程序错误和业务断言失败有不同提示。

### 7.2 功能测试与手册采集共用执行工作台

~~~text
┌ 功能测试 / 新增用户     环境：测试环境     角色：管理员        ┐
├ 用例与步骤 ─────────┬ 当前页面或最近截图 ──────┬ 结果与证据 ──┤
│ 1 打开列表 已完成   │                          │ 当前检查      │
│ 2 输入信息 已完成   │   受控浏览器画面          │ 列表是否出现  │
│ 3 提交     已完成   │   或带时间的观察快照      │ 新记录        │
│ 4 验证结果 进行中   │                          │               │
│ 5 清理数据 未开始   │                          │ 截图与日志    │
├────────────────────┴──────────────────────────┴───────────────┤
│ 当前控制者：Agent      [请求暂停] [接管操作] [查看运行记录]    │
└──────────────────────────────────────────────────────────────┘
~~~

如果尚未实现安全实时画面，使用明确标注时间的最近快照，不伪装为实时控制。接管按钮只有在 Agent 停稳、权限满足且接管通道可用时启用。接管后控制者文字变化，Agent 禁止同时操作。

功能测试模式显示断言和测试结论；手册采集模式显示操作规程、截图选用和说明草稿，不显示误导性的测试通过率。进入手册模式不自动获得额外操作权限。

截图可并排查看原图和文档用图，标出采集角色、版本、页面与来源步骤。脱敏由用户或规则确认。首版不自建完整图像编辑器；可用现成截图区域与遮罩能力，或上传已处理的派生图并保留来源。执行出现未知状态时显示“待核实提交结果”，主操作是核实，不是“立即重试”。

## 8 P06 关系与变更

首版使用可筛选关系表和影响清单，不必先实现复杂拖拽图谱。可从一条需求查看相关设计块、测试用例、执行记录和手册段落。

变更清单包含变更前后值、来源修订、受影响对象、影响理由、建议处理、处理状态。区分“文字复核”“需要重测”“需要重新截图”“引用版本待确认”。

一键全部替换只适用于明确允许的确定性字段重新渲染，不用于旧执行结果、人工批准内容或语义修改。用户确认某项无需改变时需要理由和责任人，系统保留记录。

## 9 P07 审核与交付

审核队列按文档、块或缺口定位。审核员看到本次差异、依据、自动检查结果和此前版本，而不是只看整篇生成文字。

交付面板分三个部分：选定文档及版本、阻塞项与警告、导出预览与清单。文档格式检查、资料完整性、签审、软件测试结论分别呈现。

草稿导出允许按规则携带待补项，并明确标识为草稿；正式交付要求通过该文档类型的必要门禁。签名栏由真实授权签审或公司既有流程处理，不能让 Agent 填一个人名当作已经签署。

正式发布后显示不可变交付清单及下载入口。发现错误使用“创建修订”而不是“覆盖已发布”。首版不自动向外部邮箱或外部平台发送交付包。

## 10 P08 模板与规则及 P09 系统设置

模板与规则页面向管理员：原件、机器化副本、适用场景、内容块树、字段、Skill 和提示词版本、验证用例、预览结果、发布记录。编辑已发布模板时自动创建新版本，项目升级需显示差异和影响。

系统设置包含模型连接与能力检测、测试环境和运行器、浏览器环境、凭据引用、输出办公环境、角色权限、保留与备份规则。凭据保存后默认不可回显；测试连接不向模型展示密钥。

如果模板尚未完成适配，项目可以登记该文档，但生成按钮禁用并给出“模板映射未发布”，不能默默使用一个通用提示词替代。

## 11 通用交互与状态

| 状态 | 页面行为 |
|---|---|
| 没有资料 | 明确列出缺什么、由谁补、上传或填写入口；不生成空泛占位正文 |
| 任务排队 | 显示队列和取消入口；时间未知时不编造倒计时 |
| 正在运行 | 显示当前块或步骤、已完成数量、耗时和可见工具结果 |
| 请求暂停 | 显示“暂停中”，不能立刻声称外部操作已停止 |
| 结果未知 | 锁定危险重试，提供核实和人工接管入口 |
| 生成失败 | 保留已有草稿，显示失败类型和当前可做操作 |
| 发生冲突 | 展示自己的版本、当前版本和候选修改，不覆盖 |
| 上游变化 | 旧内容仍可查看，显著标记需复核，不悄悄重写 |
| 审核驳回 | 定位被驳回块及原因，保留其他已批准块 |
| 权限不足 | 不展示敏感内容，说明申请方式而不泄露对象细节 |

进度使用可解释的分母，例如“已批准的适用内容块 / 需要批准的内容块”。生成进度、审核进度、证据准备程度分开，不用生成 token 比例伪装业务完成率。

## 12 响应式与实现验收

首版按 1440px 桌面设计，并验证 1366px 下完整工作流程；窄屏折叠全局导航和依据栏，提供切换入口，不压缩正文到不可读。移动端优先支持查看、审批和任务状态；代码编辑、复杂截图标注与浏览器接管是否支持移动端另行确认。

所有主操作有清晰名称、禁用原因、处理中状态和成功或失败反馈。键盘能到达目录、编辑区、问题列表、确认对话框并返回原焦点。错误不只使用红色。标准浏览器缩放和减少动画设置不应破坏布局。

前端不得把按钮隐藏当权限校验。每一操作在服务端同样检查角色、项目、版本、状态和任务权限。真实页面实现后需用实际长章节、多用例和多截图数据验证滚动、定位及表格溢出，本次线框不替代该验证。

技术依据见 [模板盘点与技术依据](D:/项目/智能化/docs/开发设计/附件/模板盘点与技术依据.md)。
